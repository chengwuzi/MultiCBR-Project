# DCBR：统一协议复现与新数据集搜参

本目录外层是独立移植实现；`raw/` 保留 Jiuqiang Li 的 DCBR 作者开源项目，仅供对照。目前包括第一种情况的 iFashion，以及第二种情况的 Youshu 初始配置和分轮实验管理。ReCoBR 模型保持不变，公共选模规则已按用户要求统一。

## 文件与依据

- `train.py`：独立包含 DCBR、DNN、GaussianDiffusion、数据加载、训练、评测和结果保存，不在运行时导入 `raw` 或根目录训练器。
- `config.yaml`：iFashion 沿用作者对应配置；Youshu 由 MealRec+L 初始化，目前按用户要求将基准更新为 `lambda_1=0.02、lambda_0=2000`，其余设置保留。
- `实验记录.txt`：追加保存第一种情况的运行；已经保存一次完整 iFashion 50 轮训练的成功记录。
- `搜参配置.yaml`：集中保存多数据集、多轮次、多实验的配置覆盖、ID、备注和执行状态，已安排 Youshu 第一轮 9 组实验及自动依赖。
- `run_experiments.py`：串行执行指定轮次，管理重试、重跑、历史恢复、配置状态和结果汇总；控制进程不导入 torch 或模型。
- `搜参结果.txt`：第二种情况独立汇总，已同步 Youshu 第一轮 9 组成功实验及轮次汇总。
- `test_reproduction.py`：与原始实现及 ReCoBR 评测的数值对照、小数据训练与检查点重载测试。
- `test_automation.py`：临时小数据下的自动执行、重试、成功跳过、指纹失效、中断恢复、文件锁及结果完整性检查。

## 保留与适配

| 内容 | 处理 |
|---|---|
| DCBR 推荐模型、扩散 DNN、扩散方程、ELBO/BLCC、对比损失 | 保留作者实现的计算与权重含义 |
| 每轮顺序 | 先训练扩散模块一遍，再重建 UB 图，再训练推荐模型一遍 |
| 扩散输入及候选 | 原始训练交互向量；包含全部用户，重建 Top-K 在全部组合中选择 |
| 重建图 | 保留作者的自环与对称度归一化 |
| 最终评分 | 融合 UI、BI 表示；UB 表示参与训练对比，保持作者设计 |
| 正则及优化器 | 模型内部显式 L2；推荐和去噪 Adam 均 `weight_decay=0`，防止重复施加正则 |
| 模型参数及训练轮数 | 保留作者 iFashion 设置，包括扩散 140 步、K=1、tau=0.08、训练 50 轮 |
| 随机种子 | 默认 0，沿用作者训练入口；可用 `--seed` 显式覆盖并记录。根目录 ReCoBR 的 iFashion 配置为 2026，并未声称两者默认种子相同 |
| 数据 | 读取根目录 `datasets/iFashion`；训练样本、负采样和评测屏蔽均依据原始训练交互 |
| 评测 | 对齐 ReCoBR 的全量排序、Recall/NDCG、有效用户口径、训练交互屏蔽及 Top-K `[10,20,40,80]`；仍每 5 轮评测 |
| 最佳检查点 | 统一采用作者原规则：验证 Recall@20、NDCG@20 同时严格超过此前保存检查点的对应值才更新；相等不更新，Top-40 和测试结果不参与选模 |
| 时间及产物 | 北京时间精确到秒；每次运行独立 ID、配置快照、代码和数据摘要、日志、TensorBoard、检查点、JSON 和 TXT 汇总 |

选模规则现与 DCBR、MultiCBR 作者原代码一致，ReCoBR 训练入口也统一为该规则。两项初始最佳验证值均为 0，每次接受更新后，两项基准一起取自该检查点；不维护各自独立的历史最大值，不进行指标相加。JSON 和 TXT 保存两项验证选模指标，不再使用相加的 selection_score。统一协议下的实测结果不保证逐位重现作者论文报告值。ReCoBR 现有 iFashion 配置训练 30 轮，本接入保留 DCBR 作者的 50 轮；比较报告需保留这些实际设置，不能写成相同训练轮数。

设备改为显式传递，不再硬编码 `.cuda()`；稀疏张量使用当前构造接口。扩散数据逐行转换为相同的 float32 稠密交互向量，避免先分配完整 U×B 矩阵及其张量副本；不改变用户集合、向量内容、批大小或两遍随机遍历方式。Windows 默认数据加载进程数为 0，其他系统为 10，可显式覆盖；实际值保存在配置中。重放实际配置快照时沿用其中的进程数，命令行 `--num-workers` 优先于快照设置。扩散加载仍使用 0 个工作进程。

## 运行

在项目根目录中检查配置和路径（不训练、不写实验产物）：

```bash
python DCBR/train.py --check-config
```

在装有可用 CUDA 版 PyTorch 的环境运行完整作者配置：

```bash
python -u DCBR/train.py -d iFashion -g 0 --device cuda --note "DCBR iFashion 作者配置，ReCoBR统一评测与选模"
```

也可以进入 `DCBR` 后运行 `python -u train.py ...`；默认配置位置以及数据、产物路径不依赖当前工作目录。显式传入的 `--config`、`--evaluate`、`--result-json` 按当前目录解释；配置中的 `data_path` 和 `--output-dir`、`--record-file` 的相对路径按项目根目录解释。

可用参数包括 `--seed`、`--epochs`、`--num-workers`、`--quiet`、`--config`、`--data-path`、`--output-dir`、`--record-file` 和 `--result-json`。任何实验参数覆盖都会写入实际配置。单独指定 `--epochs` 时，仍需达到至少一次评测间隔；不要把不同训练预算下的结果当作完全相同条件的实验。

## 结果与复核

每次运行产生 `DCBR/log/iFashion/<执行ID>/`，包含：

- `config.yaml`：完整实际配置快照，可作为 `--config` 重放，实体数量和设备等运行字段会重新计算。
- `training.log`、`tensorboard/`：训练与评测信息。控制台进度由 tqdm 显示，`--quiet` 可关闭批次进度，逐轮摘要仍写入日志。
- `best.pt`、`best_config.json`：同一最佳轮次的推荐参数、去噪参数、扩散状态、重建图、优化器状态、配置及数据指纹。当前入口支持重新评测，尚不提供断点续训命令。
- `result.json`：执行状态、实际配置、数据指纹、最佳轮次与指标、产物路径。失败或中断后的已有最佳结果不代表完整训练成功。

成功运行的 JSON 还包含完整训练轮数及检查点、检查点配置、实际配置快照的 SHA256，供自动化脚本复核产物是否缺失或被更改。历史 iFashion 记录保持原样，不补写新字段。

`DCBR/实验记录.txt` 保存追加式可读汇总，指标均对应验证集选中的同一检查点，明确记录从 0 计数的 best_epoch 和从 1 计数的训练轮次。根目录 `工程记录.txt` 不由程序自动修改。`--check-config` 和 `--evaluate` 不新增训练实验记录。

重算已保存检查点的验证和测试结果：

```bash
python DCBR/train.py --evaluate DCBR/log/iFashion/<执行ID>/best.pt -g 0 --device cuda
```

移动到另一台机器后可用 `--data-path ./datasets` 指定本机数据位置；数据文件指纹必须与训练时一致。评测会根据原始 UI/BI 图重算最终表示，遵循作者推理逻辑。重建 UB 图已保存用于追溯，但作者最终评分不直接使用 UB 视图。

## Youshu 初始配置的来源

用户要求从作者另两个数据集中选择较接近 Youshu 的一个，直接沿用其配置作为初始值。这里选择 **MealRec+L**。论文表 1 的 UB 稀疏度为：MealRec+L 99.8288%，MealRec+H 99.2221%；根目录 Youshu 三个 UB 划分合计 49351 条交互，对应 8039×4771 的稀疏度约 99.8713%。这是选择起点的参考，不表示不同领域、数据规模或划分具有相同分布。

Youshu 第一轮的迁移初始配置保留作者 MealRec+L 的模型参数，包括 `steps=5`、`noise_scale=1`、`lambda_0=1000`、`lambda_1=0.01`、`lambda_2=1e-5`、`tau=0.2`、`omega=0`、三视图噪声和逐层系数。公共设置使用作者 overall 配置，Top-K 扩展到统一的 `[10,20,40,80]`，种子保留作者入口的 0。训练预算按用户要求改为 **90 轮**，每 5 轮评测；作者 MealRec+L 原配置的预算为 150 轮。该配置是本工程的迁移起点。

第一轮结束后，用户依据本轮测试 Recall@20 选定 `lambda_1=0.02、lambda_0=2000`，现已将其写入基础配置，作为后续实验的当前基准。对应实验 `lambda0_2000` 的第 60 轮检查点，测试 Recall@20=0.25566120、NDCG@20=0.14389654。该决定参考了测试集，不能表述为独立于测试集确定的配置。第一轮按预先约定验证规则自动选出的优胜组合仍为 `lambda_1=0.02、lambda_0=100`，历史计划、结果与汇总保持原样。第二轮按用户新要求显式使用测试 Recall@20 选配置，训练内选 epoch 规则继续保持不变。

后续模型接入论文未覆盖的数据集时，也先从该模型作者已有数据集中选择较接近的一个，沿用其配置作为初始配置，注明选择依据；公共协议及用户明确指定的训练预算等另行说明，再通过讨论确定的实验进行调优。

原始 Youshu UB 训练交互涉及 2959 个用户，扩散部分仍遍历数据声明的全部 8039 个用户，包括没有 UB 训练交互的用户。保留作者机制，不删除或重编号这些用户，也不把 ReCoBR 的模型参数直接移植给 DCBR。

检查当前基础配置，不启动训练：

```powershell
python DCBR/train.py -d Youshu --check-config
python DCBR/run_experiments.py --list
```

## 第二种情况的集中计划

所有正式轮次集中写入 `搜参配置.yaml` 的 `rounds`，当前包含已完成的 `youshu_round_01` 和待执行的 `youshu_round_02`。脚本只执行用户确认的候选和依赖规则，不自行生成网格或扩展取值。以下展示一般轮次字段格式，实际计划以集中配置为准：

```yaml
rounds:
  - id: youshu_round_01
    dataset: Youshu
    note: 填写本轮目的、参数来源和固定条件
    overrides: {}  # 本轮公共覆盖，优先于 config.yaml 的数据集基础配置
    experiments:
      - id: initial
        note: 完整沿用 MealRec+L 初始值
        overrides: {}  # 单个实验覆盖，优先于本轮公共配置
        status: PENDING
        success: false
        fingerprint: null
        execution_ids: []
```

ID 使用 1–64 位英文字母、数字、下划线或连字符；轮次 ID 在集中配置中唯一，实验 ID 在轮次内唯一。每轮及每个实验必须填写备注。未知字段和重复 YAML 键会被拒绝，实际配置还交由训练入口检查。

`seed`、`epochs`、数据路径、批大小、层数等公共设置在本轮 `overrides` 中统一指定，不能被某一个实验单独改动。`topk`、`test_interval` 和 `neg_num` 保持基础配置的公共协议。参数是否应搜索、范围是否合适、是否涉及机制变更仍由用户和助手研究决定；程序的字段合法性检查不能替代这项判断。

`defaults` 中设置单个 GPU、设备、每次执行最多尝试次数、重试间隔、控制台更新间隔和是否实时转发训练输出。默认最多尝试 3 次，间隔 5 秒；每 30 秒显示进度和最近训练输出，完整输出始终保存在独立日志中。可设置 `stream_output: true` 逐行显示训练日志；批次进度条由自动入口关闭，减少控制台刷屏。以上运行参数可以显式修改并随执行记录保存。

配置中的路径均相对项目根目录，显式 `--plan` 路径相对当前工作目录。默认计划路径固定在本模型目录，从项目根目录或 DCBR 目录启动都可使用。

## 第二种情况的执行与结果

先预览该轮配置、指纹和依赖，再执行；预览不启动训练、不更新计划或生成实验产物。前置结果尚未产生时，预览会明确说明依赖配置和指纹未解析，不用初始值冒充后续实际值：

```powershell
python DCBR/run_experiments.py --round youshu_round_01 --dry-run
python -u DCBR/run_experiments.py --round youshu_round_01 -g 0
```

运行模式：默认 `--mode resume` 跳过已复核的历史成功实验；`--mode failed` 仅重跑当前指纹下最近失败的实验；`--mode selected --only initial` 主动重跑指定实验；`--mode all` 重跑本轮全部实验。`--gpu` 和 `--device` 可覆盖计划的设备设置。默认使用 CUDA；自动化脚本沿用当前 Python 解释器启动独立训练进程，不自动切换环境。

指纹包含完整计划生效配置、数据集、数据文件摘要、训练源码、控制器源码、设备和公共选模规则。修改代码、数据、配置或设备后，不能只凭实验 ID 或 `success: true` 跳过。历史成功还要复核完整训练轮数、实际配置、验证选中的轮次和全套指标、数据与源码摘要、内部/外部 JSON 一致性、配置快照以及检查点文件摘要。检查点损坏或缺失时，当前状态标为 INVALIDATED，默认恢复模式会重新执行。

每次执行、每次重试均有独立路径，不覆盖旧结果。默认位于 `DCBR/log/tuning/<数据集>/<轮次ID>/<实验ID>/<执行ID>/`：

- 每次执行的源码快照及 `execution.json`。
- 每次尝试的配置快照、完整 stdout、训练 TXT、外部结果 JSON 及独立训练产物目录。
- 训练产物包含原有检查点、实际配置、训练日志、TensorBoard、结果 JSON。

`DCBR/log/tuning/history.json` 是跨轮次的完整执行历史，作为恢复依据；集中 YAML 中每个实验的 `status`、`success`、`fingerprint`、`execution_ids` 是它的当前状态映射，不应手工伪造成功。运行期间不要编辑集中计划；发现人工修改后会停止，保存的历史仍可用于核查。状态更新会重新序列化 YAML，备注请保存在 `note` 字段中，普通 YAML 注释不会保留。

`搜参结果.txt` 每次执行仅追加一个完整汇总段，包含轮次与实验备注、北京时间、包含重试的总耗时、各次尝试状态和日志、实际配置、指纹、同一最佳检查点的验证及测试结果和产物路径。逐次尝试的训练 TXT 放在日志目录，不重复写进汇总。程序用文件锁与原子替换避免并发写入和重复追加；若控制进程在最终写入前崩溃，下次恢复会依据历史补齐结果及配置状态。

## Youshu 第一轮：9 组实验与自动衔接

轮次 ID 为 `youshu_round_01`，全部训练 **90 轮、种子 0、每 5 轮评测**，按下列顺序串行运行：

| 顺序 | 实验 | lambda_1 | lambda_0 |
|---|---|---|---|
| 1 | 初始对照 `initial` | 0.01 | 1000 |
| 2–5 | lambda_1 搜索 | 0.002、0.005、0.02、0.05 | 固定 1000 |
| 6–9 | lambda_0 搜索 | 自动继承前 5 组验证优胜值 | 100、500、2000、10000 |

`lambda_1=0.002/0.005` 和 `lambda_0=500/2000` 是用户讨论确认的工程补充点，其余为论文候选值。初始值与前五组一起参与选择，因此初始配置更好时会保留 `lambda_1=0.01`。后四组继承获胜实验的完整模型配置，再仅覆盖 `lambda_0`，不重新开始其他参数搜索。

跨配置比较采用用户确认的 `validation_recall20_then_ndcg20`：优先比较各实验 best epoch 的完整精度验证 Recall@20，完全相同才比较验证 NDCG@20；两项完全相同则保留配置声明顺序在前者。不按 TXT 中四舍五入的显示值比较，也不读取测试指标来决定配置。

**这与单次训练内部的选 epoch 规则分别定义。** 每个实验内部仍要求验证 Recall@20 和 NDCG@20 同时严格超过此前保存检查点的对应值，才更新 best epoch；本次没有改动该规则。

依赖通过实验字段声明，例如：

```yaml
inherit_best:
  candidates: [initial, lambda1_0002, lambda1_0005, lambda1_002, lambda1_005]
  rule: validation_recall20_then_ndcg20
overrides: {lambda_0: 100.0}
```

`inherit_best` 候选必须是同一轮中已经声明的实验，不能引用自身或尚未声明的实验，也不能出现重复候选。其规则必须与轮次 `selection_rule` 一致；未声明时默认 `validation_recall20_then_ndcg20`，第一轮继续使用该规则。第二轮显式声明 `test_recall20`，不影响其他轮次。全部前置实验都成功且通过结果与产物复核，才生成后续实际配置；前置失败或检查点失效时，后续状态为 BLOCKED，阻止用部分候选选值或使用占位配置训练。默认 `resume` 会先补齐前置训练实验，再自动继续。

启动前会用基础配置检查所有计划实验中已确定的参数覆盖，包括仍等待前置结果的实验；这份检查模板不作为实际配置或指纹。前置优胜配置确定后，程序再次检查继承后的完整实际配置，避免已知非法值在耗时的前置训练结束后才被发现。

集中 YAML 的 `resolved_config` 保存当前解析配置，`dependency_selection` 保存候选执行 ID、选择指标、优胜实验和选择规则，`blocked_by` 列出未满足的前置条件。这些均为程序维护字段。实际执行的依赖依据也保存在该次 `execution.json`、历史和 TXT 中。后续实验指纹包含前置候选的执行 ID、配置指纹及选择依据，前置被重跑或失效后，不会误用旧的后续成功状态。状态同步只更新本次指定的轮次，保留其他轮次已有状态。

控制器正常结束一次执行后，额外生成 `DCBR/log/tuning/Youshu/youshu_round_01/round_summary.json`，并在搜参 TXT 中追加对应轮次汇总。只有 9 组均有效成功才给出本轮最佳配置，否则明确记录未完成。汇总使用同一跨配置验证规则，恢复运行不会重复追加相同汇总。

指定重跑前置实验可能使后续配置失效；使用默认恢复模式完成整条依赖。`--mode selected` 只运行明确指定的实验，不隐式补跑其他前置实验；缺少前置结果时会显示 BLOCKED。

控制器对集中计划和工作目录持有操作系统文件锁，防止重复启动。子进程在 PID 保存后才放行训练，减少控制器突然退出造成的无记录训练进程。恢复时如仍存在此前训练 PID，会阻止启动新训练，请先在原服务器核查；程序不会自动终止不属于当前执行的进程。跨机器遗留 RUNNING 记录同样需要在原机器核查，PID 重用也可能需要人工确认。

失败重试与中断后的再次执行均从第 1 轮重新训练，当前不支持断点续训。正常 Ctrl+C 会停止当前子进程并记录中断；强制结束窗口或控制进程后，恢复记录会注明实际停止时间和耗时未知，不用检测时间冒充实际耗时。自动配置选择按各轮显式规则执行；第一轮按验证集，第二轮按用户要求使用测试 Recall@20，均如实留存依据。

训练子进程返回中断退出码（包括入口处理的 130）时，控制器也会记录中断并停止本轮，不将其作为普通失败自动重试。

## Youshu 第二轮：13 个新实验与历史对照

轮次 ID 为 `youshu_round_02`，固定 `lambda_1=0.02、lambda_0=2000`，所有新实验 **90 轮、seed=0、每 5 轮评测**。每个独立子进程都重新设置同一个种子，包括失败重试；种子不参与搜索，单个实验覆盖种子会被拒绝。固定种子有助于控制随机因素，不等于承诺 GPU 运算逐位一致。

| 阶段 | 新实验 | 对照及继承 |
|---|---|---|
| omega | `0.1、0.3、0.5、0.7、1.0`，5 个 | 引用第一轮 `omega=0`，保持 `tau=0.2、gamma=(0.3,0.2)` |
| tau | `0.1、0.15、0.25、0.3`，4 个 | 继承前 6 个候选的优胜完整配置；该优胜实验即 `tau=0.2` 对照 |
| gamma | `(0.1,0.4)、(0.2,0.3)、(0.25,0.25)、(0.4,0.1)`，4 个 | 继承前 10 个候选的优胜完整配置；该优胜实验即 `(0.3,0.2)` 对照 |

`gamma` 每一对表示 `(gamma_1,gamma_2)`，两者之和固定为 0.5，只调整视图间和视图内对比学习的相对比例。上述离散候选是用户确认的工程补充搜索点，不冒充作者提供的离散网格。该顺序仅为本轮 DCBR–Youshu 的具体安排。

三个阶段统一按各实验**验证选中检查点**的完整精度测试 Recall@20 选择配置。测试 Recall@20 完全相同时保留声明顺序在前者；已有对照先于新实验，因此优先保留对照。不以测试 NDCG@20 或验证指标破平局。单次训练内部仍按验证 Recall@20、NDCG@20 同时严格改善选 best epoch，测试不选择 epoch。本轮测试成绩参与搜参，不能当作独立于配置选择的测试评估。

历史对照作为一个 `reference` 候选声明，固定引用第一轮的 `lambda0_2000`、执行 ID `20261025T093608_5009e405` 及原配置指纹。它不是第 14 个训练实验，不创建新执行记录，连 `--mode all` 也不重训。程序从原服务器 `DCBR/log/tuning/history.json` 读取该执行，复核完整配置、种子、预算、数据摘要、训练源码、GPU/设备、原执行指纹、原始结果 JSON、配置快照和检查点摘要。仅控制器源码升级允许与历史不同；训练源码或配置不一致、产物缺失/损坏时，正式运行在新训练前停止，不擅自补跑或以 TXT 的八位小数冒充完整精度。
