MultiCBR 项目工作记录
记录日期：2026-10-23

本文件记录两项工作的背景、实施范围、当前进展与后续安排。
“已完成”指已经落实到当前代码并通过相应检查；“待开展”不代表已经获得实验结果。


第一项：代码规范工程

一、背景与目标

原项目中，NetEase、Youshu 使用 CBR 训练路径，iFashion 使用独立 DWT 路径。
虽然共用部分数据和评估代码，但模型、对比损失、UB 图处理及正则方式存在差异，
增加了维护成本，也使不同数据集的实验目标难以统一解释。

本项工作的核心目标：以 NetEase、Youshu 的现有 CBR 实现为基准，将 iFashion
合入同一条训练主线，清理退出使用的代码和配置。NetEase、Youshu 能不动就不动，
不借本次整理更改它们的算法、超参数和随机采样行为。

二、统一后的训练链路

1. 入口统一：train.py 的 main 读取数据集配置，再进入 run_cbr_training。
2. 数据统一：utility.py 读取 UB、UI、BI 关系及训练、验证、测试划分。
3. 采样统一：使用原始 UB 训练正交互，随机采集该用户未观测的负 bundle。
4. 模型统一：三个数据集均创建 AnchorViewBundleNet。
5. 重构接口统一：latent_rebuild 控制是否在每轮推荐训练前进行扩散训练和 UB 筛边。
6. 表示统一：共用三视图传播、邻居聚合、残差补充和固定权重融合代码。
7. 推荐目标统一：BPR + c_lambda × 融合后对比 + anchor_cl_lambda × 融合前对比。
8. 更新统一：推荐模型使用 Adam，weight_decay=l2_reg。
9. 评估统一：全量 bundle 排序，屏蔽原始训练交互，统计 Recall 和 NDCG。
10. 选模统一：按验证集 Recall@20 + Recall@40 + NDCG@20 + NDCG@40 选择最佳模型。

融合前对比：先对 batch 内用户 ID 和正 bundle ID 去重，再分别计算用户侧和
bundle 侧的 UB→UI、UB→BI 四项对比，按内部权重求和。
融合后对比：对融合后的用户、正 bundle 表示分别计算自身配对 InfoNCE，再取平均。
旧 DWT 的独立跨视图和视图内对比不再保留。

三、已经完成的改动

1. iFashion 已切换到 CBR 主线，删除旧 DWT 模型、训练函数、图配置解析及专属参数。
2. iFashion 的扩散参数从 dwt 迁入 latent_rebuild，保留每轮训练重构器及 Top-3 筛边。
3. iFashion 开启融合前对比，融合后对比权重、温度也由共用配置实际控制。
4. iFashion 的 UB 图不再加入旧 DWT 自环，种子设置与正则方式跟随 CBR 主线。
5. 清理废弃负采样占位参数、未读取的属性和导入、重复参数覆盖、空对比日志字典。
6. 评估关闭梯度记录；训练结束关闭 TensorBoard writer。
7. 保存当前组合实际使用的学习率，修正选模提示和乱码日志。
8. 输出路径加入配置摘要，区分种子、对比参数和扩散参数不同的实验。

输出命名说明：相同配置重跑仍会复用路径；需要保留独立重复实验时，应改变 seed
或 --info。输出命名调整适用于三个数据集，但不改变训练损失或参数更新规则。

四、三个数据集保留的配置差异

NetEase：扩散重构关闭；UB/UI/BI 融合权重为 0.5/0.2/0.3；
         UI、BI 两项残差系数为 0、0.35；原有配置保持不变。
Youshu：扩散重构关闭；UB/UI/BI 融合权重为 0.35/0.15/0.5；

“统一”指配置结构、代码和损失定义一致，不要求各数据集使用相同参数值或模块开关。

第二项：iFashion 调参工程

一、总策略：按影响层级分档，逐档缩小搜索范围

本项工作要解决：统一 CBR 路线下，先调哪些参数，怎样公平比较，怎样用有限实验
找到稳定的好配置。iFashion 的旧 DWT 最优参数只作起点，不认定为新路线的最佳值。
当前状态：代码迁移完成，服务器调参尚未开展；以下是待执行策略，不是已有实验结论。

优先级与执行顺序：
前置准备：建立参考配置，确定公平的训练预算和实验方式。
第一档，必调：推荐学习率、两类对比权重、两类温度。先解决新训练目标如何平衡。
第二档，重点调：rebuild_k、UI/BI 融合比例、三类噪声。再解决使用什么图信号及如何融合。
第三档，细调：扩散训练参数、推荐正则、层融合权重。围绕有效方案做局部提升。
第四档，可选探索：容量、传播层数、残差、内部对比权重等。预算充足时再做。
最后收尾：回查关键交互，做多种子复验与消融，冻结最终配置。

核心方法是“分档、粗搜、局部细搜、交互回查”，不是所有参数一次性笛卡尔积。
档位是针对这次损失迁移的实验优先级，不是对参数影响大小已经做出的实验证明。
预算有限时，优先完成前两档和最终复验；不要求把第三、四档全部搜索完。

二、前置准备：先保证比较公平

1. 保存当前 config.yaml 中的 iFashion 配置为参考配置 R0，完整记录而不只记录几个参数。
   起点：lr=0.001；c_lambda=0.1；anchor_cl_lambda=0.07；两类温度均为 0.2；
   rebuild_k=3；num_steps=12；set_loss_weight=0.05；融合权重=[0,0.5,0.5]；
   噪声 UB/UI/BI=0.05/0/0.2；两项残差=0；其余取当前配置。

2. 搜索阶段统一使用 seed=2026。每个候选配置都独立启动一个新进程，从头训练。
   当前代码只在 main 中设置一次种子，同进程跑多个参数组合不会为每组重新设置种子，
   因此不能把“列表里放很多值，一次启动全部跑完”作为严格公平的主搜索方式。
   不更改现有种子逻辑，以免影响 NetEase、Youshu；实验时所有候选列表先写成单值。

3. 固定数据划分、外部 embedding 文件、batch_size_train=2048、neg_num=1、Noise 增强、
   embedding_sizes=[64]、num_layerss=[2]、test_interval=5、四个对比内部权重=1。
   除正在研究的参数之外，其他设置均冻结。用户侧和 bundle 侧融合前对比先都开启。

4. 训练轮数先做预算检查，不把 epochs=30 当作已经充分收敛。
   先观察 R0 在 30、60 轮预算下的验证曲线；若最佳值持续出现在末两次评估且仍上升，
   再以 30 轮为步长增加预算。每次延长均重新启动，当前 checkpoint 不支持完整续训。
   同一批参与排名的候选使用相同轮数 E 和评估间隔，不能直接比较 30 轮和 90 轮成绩。
   若后续优秀候选在 E 轮末仍明显上升，统一扩大该批决赛候选的预算后重新比较。

5. 所有选择都以验证分数 S 为准：
   S = Recall_V@20 + Recall_V@40 + NDCG_V@20 + NDCG_V@40。
   用每次训练验证集选出的最佳 checkpoint 比较候选，不用最后一轮成绩替代。
   虽然脚本会同时打印测试指标，调参时不能用测试集挑参数。

下文候选集合均为围绕当前实现提出的起始范围，不是已验证最优范围。
每组先跑当前点和少量代表点；确认有效方向后再补齐范围，不必把所有候选全部跑完。

三、第一档：新训练目标与基础优化，必须优先完成

本档回答：BPR、融合前对比、融合后对比怎样平衡，推荐模型能否有效学习。
固定重构器全部配置、rebuild_k=3、融合权重、噪声、层权重和残差设置。

步骤 1：粗查推荐学习率，排除明显不合适的优化速度。
参数：lrs，当前 [0.001]；候选值 0.0005、0.001、0.002。
暂用 R0 的两类损失设置，选验证分数较好且训练稳定的学习率作为接下来的基点。
这只是初选，不能据此认定学习率在后续损失权重改变后仍然最优。

步骤 2：先粗搜融合前对比权重。
参数：anchor_cl.anchor_cl_lambda，当前 0.07。
候选值：0、0.001、0.003、0.01、0.03、0.07、0.1。
固定 c_lambdas=[0.1]，固定两类温度为 0.2，其他配置不变。
先看 0、小权重、中权重、当前点的趋势，再补搜有希望的区间，保留前两名。
融合前是四项求和，不能因为 0.07 小于 0.1，就认为其作用一定更弱。

步骤 3：粗搜融合后对比权重。
参数：c_lambdas，当前 [0.1]；候选值 0、0.01、0.03、0.1、0.3。
先固定步骤 2 的最佳融合前权重进行搜索，保留前两名。
再把两类权重各自保留的两个值做最多 2×2 的组合确认，避免完全依赖单项搜索顺序。
0 是用于识别贡献的消融点，不预先决定最终关闭哪一类对比；关闭项不再搜索其温度。

步骤 4：分别搜索两类温度。
融合前参数：anchor_cl.temp；融合后参数：c_temps；当前均为 0.2。
候选值均可从 0.05、0.1、0.2、0.3、0.5 中选取。
先固定融合后温度，搜索融合前温度；再固定新融合前温度，搜索融合后温度。
两类温度无需相同。温度改变梯度分布，权重改变整项贡献，二者不能互相替代。

步骤 5：在优胜区域细搜，并回查交互。
例如某权重在 0.01 和 0.03 之间较好，就补查中间点，而不是继续向无效方向扩大。
先各保留两组完整“融合前权重+温度”和“融合后权重+温度”，再做最多四组组合比较；
随后用完整优胜配置回查初选学习率及其相邻值。不要展开所有权重和温度的全网格。
如果候选已经验证过且完整配置、预算一致，可以复用该记录，不必重复运行。

本档结束条件：确定 1～2 组稳定、预算充分、优于或不差于参考配置的完整推荐损失设置。
如果最优点在搜索边界，沿该方向补少量点；如果没有提升，就保留参考点，不强行更换。

四、第二档：图信号与视图融合，第一档之后重点完成

本档回答：用多强的 UB 筛边、UI/BI 各占多少，以及多大噪声更合适。
使用第一档最佳完整配置；如果前两名接近，先在最佳上粗搜，再给第二名做少量交叉确认。

步骤 1：搜索 UB 筛边强度。
参数：latent_rebuild.rebuild_k，当前 3；候选值 1、3、5、7、10。
rebuild_k 是从每用户原始已观测 bundle 中最多保留几条，不是新增边数，也不减少 BPR
正样本。禁止设为 0；关闭重构应使用 latent_rebuild.enabled=false。
先找过强筛边与较宽松筛边的趋势，在较好区域补相邻整数，保留前两名。
此时先固定重构器 lr、num_steps、set_loss_weight，不同时改变筛边算法的其他条件。

步骤 2：先调 UI/BI 配比，不立即给 UB 加最终评分权重。
参数：fusion_weights.modal_weight=[0,w,1-w]。
w 候选值：0.25、0.4、0.5、0.6、0.75；当前 w=0.5。
UB 权重为 0 时仍作为融合前对比的 anchor。先保留这一设定，便于明确 UI/BI 的平衡。
选择较好的两个配比，与两个 rebuild_k 做最多四组交叉确认，因为图筛边和融合会共同
影响推荐训练。更改融合比之后，需要局部回查第一档的对比权重，而非默认完全独立。

步骤 3：逐个搜索三类噪声幅度。
UB_ratios：当前 [0.05]；候选 0、0.025、0.05、0.1、0.2。
BI_ratios：当前 [0.2]；候选 0、0.05、0.1、0.2、0.3。
UI_ratios：当前 [0]；候选 0、0.025、0.05、0.1。
建议先 UB，再 BI，最后 UI；每次仅放开一个，更新基点后再调下一个。
当前是 Noise 模式，这些值是特征噪声幅度，不是删边率。BI 噪声还作用于 UI 视图中
通过 BI 关系聚合 bundle 的步骤，因此不能把各项理解为完全互不影响。
最后在较好噪声组合附近复查两个候选，避免只保留顺序搜索的偶然结果。

本档结束条件：得到一套明确的筛边强度、UI/BI 配比与噪声设置，并对第一档的关键
损失参数做过局部回查。预算有限时，到此进入最终多种子复验即可。

五、第三档：辅助训练与层权重，围绕优胜方案细调

本档不从头大范围搜索，固定前两档的优胜方案，每次只调整一项。

1. 重构器学习率：latent_rebuild.latent_diffusion_lr，当前 0.001。
   候选 0.0003、0.001、0.003。它独立于推荐模型 lrs，不要同时修改两者。
2. 重构步数：latent_rebuild.latent_diffusion_num_steps，当前 12。
   候选 6、9、12、16。步数同时影响训练加噪范围和筛边前迭代预测，不能只按耗时选择。
3. 集合损失权重：latent_rebuild.latent_diffusion_set_loss_weight，当前 0.05。
   候选 0、0.01、0.05、0.1。0 只关闭集合约束，MSE 去噪目标仍然保留。
4. 推荐正则：l2_regs，当前 [0.00001]。
   候选 0、0.000001、0.00001、0.0001；观察验证改善和过拟合，不只看训练损失下降。
5. 层融合权重：先固定两层传播，分别调整 UB_layer、UI_layer、BI_layer。
   每个视图比较当前值与 [0.6,0.3,0.1]、[0.2,0.4,0.4] 等代表方案。
   一次只改一个视图，列表长度固定为三项，权重和保持为 1。

上述顺序是执行建议。某项没有收益就保留原值，不为“调过所有参数”消耗预算。
重构器参数变化后，补查最佳 rebuild_k 附近；层权重变化后，补查最佳融合比例附近。
本档输出是完整候选配置及其增益来源，不是把各单项最优值未经复验直接拼起来。

六、第四档：可选结构探索，不作为第一轮必做项

仅当前三档收益有限或预算充足时开展；每类单独立项比较，不能同时改变多个结构。

1. 最终融合加入 UB：在最佳 UI/BI 比例 w 附近比较 [u,(1-u)w,(1-u)(1-w)]，
   u 可取 0、0.05、0.1。它改变 UB 直接参与评分的程度，应与 UI/BI 配比搜索分开记录。
2. 子视图残差：ui_bundle_user_agg_beta、bi_user_bundle_agg_beta 当前均为 0。
   候选可取 0、0.05、0.1、0.2、0.35。先分别单开，再对有效方向做组合，不先扫双网格。
   开启后重构 UB 还会影响残差聚合，必须回查 rebuild_k，不能把它当作纯数值微调。
3. 推荐容量：embedding_sizes 比较 [64]、[128]；num_layerss 可研究 [1]、[2]、[3]。
   修改层数时，三个视图层权重列表长度必须同步等于层数+1；训练预算也需检查。
4. 融合前内部结构：user_cl、bundle_cl 先做两侧贡献消融；若确有不平衡，再调整四项
   ub_ui_user_weight、ub_bi_user_weight、ub_ui_bundle_weight、ub_bi_bundle_weight。
   不要同时缩放四个内部权重和 anchor_cl_lambda，因为会重复改变整体损失尺度。
5. 重构器容量与正则：hidden_dim、denoiser_layers、dropout、weight_decay、time_dim，
   以及 beta_start/beta_end、重置策略。它们初期保持当前值，仅在有明确假设时单独研究。

第四档第 1、2 项有额外边界：扩散开启时，给 UB 非零融合权重或开启 UB 残差后，
最终评分会直接依赖当轮重构图。当前 checkpoint 没有保存该图，训练内的验证和测试
可以计算，但若要独立加载最佳模型复评，需要先补齐同轮重构图的保存与恢复。
未补齐前，这两项只作为训练内探索，不能声称模型文件已经完整支持独立复现。

batch_size_train 初期固定，因为它同时改变对比负样本规模和每轮推荐更新次数。
重构训练 batch 也先固定；batch_size_test、latent_diffusion_infer_batch_size 主要按显存
和速度安排，不列为核心效果搜索项。路径、topk、Noise 下的 ed_interval 不作为调参对象。

七、每档通用的比较、回退与晋级规则

1. 同一档先固定其他配置做粗搜，只保留前两名，不把所有历史候选都带到下一档。
2. 在优胜点附近细搜一次；边界点最好时补搜边界外少量值，不能直接宣布边界即最优。
3. 参数存在交互时，用保留的两个值做小规模组合验证，再进入下一档；不要求全局穷举。
4. 新配置没有验证增益时回退到上一基点；训练不稳定或未收敛的候选不能直接当作无效。
5. 单次微小领先只列为候选，不能认定为稳定改进；最终用预先确定的多个种子确认。
6. 更改图、融合或模型容量后，允许局部回查损失权重和学习率，避免一次顺序搜索定终身。

八、最终确认：冻结候选，再做复验和机制对照

1. 选出最好的 1～2 组完整配置，与采用相同训练预算的 R0 比较。
   预先固定复验种子为 2026、2027、2028，不根据结果挑选“好种子”。
   每个种子每个配置都独立启动；分别按各自验证集选择 checkpoint，报告均值和标准差。
2. 如果候选间差距与波动接近，暂不宣布胜负；可预先增加 2029、2030 两个种子确认。
3. 对冻结的完整配置做消融：两类对比均关闭、仅融合前、仅融合后、两类均开启，
   再比较保留/关闭重构。首轮消融固定其他参数，不为每个消融另找不同最优参数。
   这是模块贡献对照，不等于证明每个变体在各自重新调参后也有相同排名。
4. 配置中关闭融合后贡献用 c_lambdas=[0.0]；关闭融合前用 anchor_cl.enabled=false；
   关闭重构用 latent_rebuild.enabled=false。不要只新增单值 c_lambda，它会被列表覆盖。
5. 最终将全部实际参数、代码版本、训练预算、各个 seed 的最佳轮次、验证 S、测试四档
   Recall/NDCG、耗时和输出路径写入实验结果存档/ifashion.txt。不填入尚未运行的成绩。
