MultiCBR 项目工作说明

一、当前调参工作的目标

本项目当前的主要工作，不是继续改模型结构，而是围绕已经接入到 MultiCBR 中的扩散式 UB 图重建模块做调参研究。

当前改造的核心语义如下：
1. NetEase 和 Youshu 继续使用 MultiCBR 主训练逻辑。
2. 不切换到 iFashion 的 DWT 主分支。
3. 仅将 iFashion 中“扩散模块 + UB 图重建”的思想迁移到 NetEase 和 Youshu。
4. 扩散模块的作用是：
   - 读取外部预训练 UB 用户/礼包表示；
   - 对每个用户的训练期 bundle 历史做 latent diffusion 去噪；
   - 在该用户原始训练 bundle 集合内部重新打分；
   - 取 top-k；
   - 用这些 top-k 边重建一张新的 UB 图；
   - 将这张新的 UB 图注入 MultiCBR，用于训练和评估阶段的 UB message passing。

几个关键语义已经确认：
1. top-k 以外的原始训练正交互，没有被当成显式负样本。
2. 扩散模块改变的是图传播结构，不改变监督标签定义。
3. val/test 不参与建图，不泄漏信息。
4. 评估时的 ground truth 仍来自原始 tune/test 划分文件。

当前调参工作的主线是：
1. 先固定 MultiCBR 本身结构和主训练逻辑不动；
2. 优先搜索扩散重建模块的关键参数；
3. 目标是提升重点关注指标，尤其是 Recall/NDCG 的 Top10 和 Top20。


二、Youshu 已完成的三阶段调参工作

Youshu 这条线已经完成三阶段搜参，可以视为阶段性结束。

当前对 Youshu 的评估重点，后期已经收缩为：
1. Top10 Recall
2. Top10 NDCG
3. Top20 Recall
4. Top20 NDCG

基于这个关注口径，Youshu 当前暂定最佳参数为：
- rebuild_k = 7
- latent_diffusion_set_loss_weight = 0.04
- latent_diffusion_num_steps = 9
- latent_diffusion_lr = 1.0e-3

说明：
1. 这个“暂定最佳”是按当前重点只看 Top10 / Top20 得出的。
2. 如果以后重新把 Top40 / Top80 也纳入主要目标，可能会重新考虑 step 或 weight。

2. 第二阶段调参：latent_diffusion_set_loss_weight

固定参数：

搜索结果摘要：

  - TOP20: 0.28708 / 0.17101
- weight=0.04
  - TOP10: 0.20723 / 0.14824
  - TOP20: 0.28882 / 0.17161

  - TOP10: 0.20461 / 0.14808
  - TOP20: 0.28787 / 0.17199
- weight=0.02
  - TOP10: 0.20529 / 0.14801
  - TOP20: 0.28874 / 0.17196
- weight=0.06
  - TOP10: 0.20663 / 0.14797
  - TOP20: 0.28877 / 0.17157
- weight=0.08
  - TOP10: 0.15397 / 0.10991

阶段性结论：
1. latent_diffusion_set_loss_weight 不是第一主导参数，但也不是无关参数。

3. 但 0.08 明显崩掉，说明这个参数存在明显的失效区间，不能设太大。
4. 如果只看 Top10 / Top20 的 Recall + NDCG 综合平衡，0.04 优于 0.03。
5. 因此进入第三阶段时，固定 latent_diffusion_set_loss_weight = 0.04。

四、后续 NetEase 的搜参工作

后续工作的主线已经明确：停止继续深挖 Youshu，把调参主战场转到 NetEase。

当前对 NetEase 的整体判断：
1. 它比 Youshu 更值得继续投入精力，因为 active users 覆盖几乎全体用户。
2. 它比 iFashion 更稀疏，但没有 Youshu 那么多低度 active user。
3. 因此，NetEase 的扩散 UB 重建参数应当：
   - 比 iFashion 更保守；
   - 比 Youshu 稍微大胆一点。


1. NetEase 关键参数的推荐起始值

基于：
1. iFashion 当前已搜索出的暂定最佳参数；
2. Youshu 已完成的三阶段搜参结果；
3. NetEase 自身 active user 的 UB 度、UI/UB 比、bundle 结构统计；

当前对 NetEase 最推荐的起始关键参数是：
- rebuild_k = 9
- latent_diffusion_set_loss_weight = 0.05
- latent_diffusion_num_steps = 12
- latent_diffusion_lr = 1.0e-3
- latent_diffusion_batch_size = 1024

这是当前最推荐首先尝试的一组配置。

理由：
1. rebuild_k
   - iFashion 的 active UB 历史显著更长，所以它的 k=3 不能直接搬。
   - NetEase active user 平均 UB 历史约 11.77，中位数 8。
   - k=9 时保留约 63.93% 的训练 UB 边，更像一个平衡点。
   - k=7 偏保守，k=12 开始有退化回原图的风险。
2. latent_diffusion_set_loss_weight
   - NetEase 的用户行为更完整，bundle BI 结构更强，适合稍微更保守一点的 set consistency。
   - 因此优先保留 0.05，而不是先用 Youshu 当前更优的 0.04。
3. num_steps
   - 12 是当前各数据集都比较稳的起点。
   - step 通常不是第一主导参数，因此暂时不动。
4. lr
   - 1e-3 是目前最合理的默认起点。


2. NetEase 第一阶段搜参工作的建议顺序

第一阶段优先仍然是 rebuild_k。

如果实验预算有限，建议先跑：
- k = 7
- k = 9
- k = 12

如果预算稍宽裕，建议跑：
- k = 5
- k = 7
- k = 9
- k = 12
- k = 15

当前主观预判：
1. NetEase 最有希望的 rebuild_k 区间是 7 到 10。
2. 其中 k=9 是当前最看好的起点。


3. NetEase 后续搜参优先级

如果第一阶段先把 k 定下来，后续优先级建议如下：
1. rebuild_k
2. latent_diffusion_set_loss_weight
3. latent_diffusion_num_steps
4. latent_diffusion_lr
5. latent_diffusion_batch_size

说明：
1. 当前 batch_size=1024 对 NetEase 不像对 Youshu 那么敏感，因为 NetEase active users 数量更大。
2. 因此 batch_size 不必优先搜索。
3. 如果后续发现训练稳定性问题，再考虑 batch_size 和 lr 的联动调整。


4. NetEase 后续对指标的关注口径

后续如果与 Youshu 保持一致，也建议优先看：
1. TOP20 NDCG
2. TOP10 NDCG
3. TOP20 Recall
4. TOP10 Recall

如果后续需求重新变动，再决定是否把 Top40 / Top80 重新纳入核心判断指标。
