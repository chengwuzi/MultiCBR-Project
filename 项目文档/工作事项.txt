MultiCBR 项目工作记录
记录日期：2026-10-23

本文件记录三项工作的背景、实施范围、当前进展与后续安排。
“已完成”指已经落实到当前代码并通过相应检查；“待开展”不代表已经获得实验结果。


第一项：代码规范工程

一、背景与目标

原项目中，NetEase、Youshu 使用 CBR 训练路径，iFashion 使用独立 DWT 路径。
虽然共用部分数据和评估代码，但模型、对比损失、UB 图处理及正则方式存在差异，
增加了维护成本，也使不同数据集的实验目标难以统一解释。

本项工作的核心目标：以 NetEase、Youshu 的现有 CBR 实现为基准，将 iFashion
合入同一条训练主线，清理退出使用的代码和配置。NetEase、Youshu 能不动就不动，
不借本次整理更改它们的算法、超参数和随机采样行为。

二、统一后的训练链路

1. 入口统一：train.py 的 main 读取数据集配置，再进入 run_cbr_training。
2. 数据统一：utility.py 读取 UB、UI、BI 关系及训练、验证、测试划分。
3. 采样统一：使用原始 UB 训练正交互，随机采集该用户未观测的负 bundle。
4. 模型统一：三个数据集均创建 AnchorViewBundleNet。
5. 重构接口统一：latent_rebuild 控制是否在每轮推荐训练前进行扩散训练和 UB 筛边。
6. 表示统一：共用三视图传播、邻居聚合、残差补充和固定权重融合代码。
7. 推荐目标统一：BPR + c_lambda × 融合后对比 + anchor_cl_lambda × 融合前对比。
8. 更新统一：推荐模型使用 Adam，weight_decay=l2_reg。
9. 评估统一：全量 bundle 排序，屏蔽原始训练交互，统计 Recall 和 NDCG。
10. 选模统一：按验证集 Recall@20 + Recall@40 + NDCG@20 + NDCG@40 选择最佳模型。

融合前对比：先对 batch 内用户 ID 和正 bundle ID 去重，再分别计算用户侧和
bundle 侧的 UB→UI、UB→BI 四项对比，按内部权重求和。
融合后对比：对融合后的用户、正 bundle 表示分别计算自身配对 InfoNCE，再取平均。
旧 DWT 的独立跨视图和视图内对比不再保留。

三、已经完成的改动

1. iFashion 已切换到 CBR 主线，删除旧 DWT 模型、训练函数、图配置解析及专属参数。
2. iFashion 的扩散参数从 dwt 迁入 latent_rebuild，保留每轮训练重构器及 Top-3 筛边。
3. iFashion 开启融合前对比，融合后对比权重、温度也由共用配置实际控制。
4. iFashion 的 UB 图不再加入旧 DWT 自环，种子设置与正则方式跟随 CBR 主线。
5. 清理废弃负采样占位参数、未读取的属性和导入、重复参数覆盖、空对比日志字典。
6. 评估关闭梯度记录；训练结束关闭 TensorBoard writer。
7. 保存当前组合实际使用的学习率，修正选模提示和乱码日志。
8. 输出路径加入配置摘要，区分种子、对比参数和扩散参数不同的实验。

输出命名说明：相同配置重跑仍会复用路径；需要保留独立重复实验时，应改变 seed
或 --info。输出命名调整适用于三个数据集，但不改变训练损失或参数更新规则。

第二项：iFashion 调参工程

一、已经确定的主顺序

本项工作按用户确定的顺序执行，不再先搜融合前对比，也不把重构 Top-K 放到融合权重之前。
当前状态：统一 CBR 路线已完成，服务器调参尚未开始；以下为待执行方案，不是实验结果。

第一阶段：关闭融合前对比，先调 c_lambdas、c_temps，建立融合后对比基线。
第二阶段：固定第一阶段优胜设置，开启融合前对比，调其权重与温度。
第三阶段：固定两类对比设置，调 fusion_weights.modal_weight 三视图融合权重。
第四阶段：固定前三阶段优胜设置，调 latent_rebuild 的 Top-K 及相关参数。
最后：在最终配置附近少量回查前阶段参数，做多种子复验和消融，再冻结方案。

核心方法：每阶段只放开本阶段参数，粗搜后局部细搜，保留完整优胜配置传给下一阶段。
阶段内的“最佳”指当前其他设置固定时、已搜索范围中的最佳，不承诺全局最优。

二、共同实验约束

1. 仅调整 iFashion；NetEase、Youshu 的配置与共用算法保持不变。README 不改动。
2. 当前起点：推荐 lr=0.001、l2_reg=0.00001、batch=2048、维度=64、传播两层、
   Noise 增强、UB/UI/BI 噪声=0.05/0/0.2、两项残差=0；初期均固定。
   重构初值为 enabled=true、rebuild_k=3、num_steps=12、set_loss_weight=0.05、
   重构 lr=0.001，其余沿用现有配置。学习率、噪声、容量不插入本轮主搜索顺序。
3. 先保存当前原始完整配置 R0；第一阶段另记录关闭融合前对比后的基线 B0。
   R0 的 anchor_cl 当前开启、权重为 0.07；B0 才是第一阶段实际使用的起点。
4. 搜索阶段固定 seed=2026；每个候选独立启动新进程，从头训练，候选列表先写为单值。
   当前同进程网格不会为每组重新设置种子，不能把不同执行位置的组合当作严格同初始化比较。
5. 同一组候选使用相同训练预算和评估间隔。当前 epochs=30、test_interval=5；
   若验证最佳值总落在末两次评估且仍上升，再统一扩大该组优秀候选的预算后重跑。
   当前 checkpoint 不支持完整续训，不能只多跑后面的轮次，也不能混比不同预算的成绩。
6. 统一按验证集分数 S 排名：
   S = Recall_V@20 + Recall_V@40 + NDCG_V@20 + NDCG_V@40。
   使用每次训练验证集选出的最佳 checkpoint。脚本打印的测试指标不用于挑选参数。
7. 后文候选范围是起步建议，不是验证结论；先跑代表点，看到有效方向再补点。
   每次保留完整配置及前两名，避免只记一个参数或仅凭单次微小领先认定改进。

三、第一阶段：关闭融合前对比，先建立融合后对比基线

目标：先确定 BPR 与融合后对比的合适平衡，不让融合前对比干扰这一步判断。

关闭方式：设置 anchor_cl.enabled=false，可直接跳过融合前对比计算。
如果希望总开关仍为 true，也可以设置 anchor_cl.anchor_cl_lambda=0.0，使其贡献为零，
但仍会计算该损失。不要把整个 anchor_cl 配置块写成数字 0，代码要求这里是字典。
本方案第一阶段优先使用 enabled=false；user_cl、bundle_cl 和内部权重保留不改。

此时推荐目标：L = BPR + c_lambda × 融合后对比损失。
固定 modal_weight=[0,0.5,0.5]、重构全部初始参数、噪声、层权重及残差。
由于 UB 最终权重为 0、残差为 0、融合前对比已关闭，UB 重构暂时没有参与推荐目标的
有效学习路径；仍保持重构开关和调度不变，以免额外改变运行条件及随机数消耗。
不要在这一阶段同时比较不同 rebuild_k。

步骤 A：先搜融合后对比权重 c_lambdas。
当前值 [0.1]；粗搜候选可取 0、0.01、0.03、0.1、0.3，先固定 c_temps=[0.2]。
每次实际配置只放一个值，例如 c_lambdas=[0.03]，独立运行并记录验证 S。
0 作为纯 BPR 对照。若最优在区间边界，沿该方向补少量点；在较好区间再补中间点。

步骤 B：固定较好的非零权重，再搜融合后温度 c_temps。
候选可取 0.05、0.1、0.2、0.3、0.5。
若权重 0 暂时领先，仍保留它作对照，同时在最好的非零权重下检查温度，避免过早否定该损失。
权重为 0 的候选不再搜索温度，因为其温度对推荐目标不生效。

步骤 C：小范围联合确认。
各保留两个权重、两个温度，最多做 2×2 组合确认，不把全范围全部交叉。
选择完整的 (c_lambda, c_temp) 优胜组合 P1，记录验证分数、最佳轮次和损失量级。
这一阶段得到的是“没有融合前对比时”的融合后基线，作为第二阶段的固定起点。

四、第二阶段：开启融合前对比，调其权重和温度

目标：在 P1 基础上引入 UB 锚定约束，确定它的有效强度与温度。

固定第一阶段选出的 c_lambdas、c_temps；其他图、融合和重构设置仍不动。
设置 anchor_cl.enabled=true，user_cl=true、bundle_cl=true，四个内部权重均保持 1。
这里要调的是 anchor_cl.anchor_cl_lambda 和 anchor_cl.temp，不是另加旧 DWT 对比损失。
此时推荐目标：L = BPR + 固定的 c_lambda × 融合后对比 + anchor_cl_lambda × 融合前对比。

步骤 A：先搜融合前总权重 anchor_cl.anchor_cl_lambda。
候选可取 0、0.001、0.003、0.01、0.03、0.07、0.1，先固定 anchor_cl.temp=0.2。
0 对应不施加该项约束的对照；先试少量代表点，再补较好区间，不必一次跑完所有点。
融合前是四项求和，融合后是两项平均，因此不能只按 lambda 数值大小比较两项的作用。

步骤 B：固定较好的非零融合前权重，搜索 anchor_cl.temp。
候选可取 0.05、0.1、0.2、0.3、0.5；它无需等于第一阶段的 c_temps。
如果零权重暂时最好，处理方法与第一阶段相同：保留对照，并检查最好非零候选的温度。

步骤 C：在前两名权重、前两名温度之间做最多四组局部组合，得到完整优胜配置 P2。
本阶段先不重新展开第一阶段搜索；两个阶段存在耦合，留到最终配置附近局部回查。
若开启融合前对比没有提升，要保留真实结果和零权重对照，不强行把某个非零值写成最佳。

五、第三阶段：调三视图融合权重 modal_weight

目标：在两类损失设置固定后，确定 UB、UI、BI 对最终推荐评分的贡献。
本阶段固定 P2 的所有损失参数和现有重构设置，三个融合权重在本阶段内研究。
三个值的顺序严格为 [UB,UI,BI]，非负且权重和保持为 1，避免同时改变整体表示尺度。

步骤 A：先沿当前 UB=0 的边界，调整 UI/BI 配比。
使用 modal_weight=[0,w,1-w]，w 可取 0.25、0.4、0.5、0.6、0.75。
当前点为 [0,0.5,0.5]；选择较好的 UI/BI 配比，并在附近补少量值。

步骤 B：在本阶段继续研究 UB 的非零权重，不另移到其他阶段。
使用 modal_weight=[u,(1-u)w,(1-u)(1-w)]。
u 可先取 0、0.05、0.1、0.2；先固定步骤 A 较好的 w，再在较好 u 附近局部调整 w。
只保留 1～2 组完整融合权重，不把三个数分别独立搜索后再拼起来。
如果最好的结果仍为 UB=0，就保留它，不预设三视图必须都有非零最终融合权重。
UB=0 时仍可通过第二阶段开启的融合前对比参与训练。

产出 P3：包含固定的两类对比设置和本阶段优胜融合权重的完整配置。

保存边界：当扩散开启且 UB 最终权重非零时，最终评分直接依赖当轮重构 UB 图。
训练内的验证和测试可以正常计算；但当前 checkpoint 没保存该图，若要独立加载最佳
模型复评，需要先补齐同轮重构图的保存和恢复。未补齐前不能声称模型文件已完整支持
这类配置的独立复现。本轮只记录该限制，不在调参策略修改中改动模型或保存代码。

六、第四阶段：调重构 Top-K，再调相关参数

目标：在损失与融合方式确定后，优化 UB 筛边的强度与质量。
固定 P3 的损失和融合设置；不要一边变 K，一边变对比权重或 modal_weight。

步骤 A：优先搜索 latent_rebuild.rebuild_k。
当前值 3；粗搜可取 1、3、5、7、10，在较好位置附近补相邻整数。
它是每用户原始已观测 bundle 中最多保留的数量，不新增未观测边，也不减少 BPR 正样本。
禁止设为 0。关闭重构应使用 latent_rebuild.enabled=false，作为单独对照记录。
先固定重构 lr=0.001、num_steps=12、set_loss_weight=0.05，保留较好的两个 K。

步骤 B：固定优胜 K，依次调整重构器的相关参数。
1. latent_diffusion_lr：当前 0.001；候选 0.0003、0.001、0.003。
2. latent_diffusion_num_steps：当前 12；候选 6、9、12、16。
3. latent_diffusion_set_loss_weight：当前 0.05；候选 0、0.01、0.05、0.1。
以上三个键均位于 latent_rebuild 内部。每次只调一项，其他继承上一步优胜配置。
步数同时影响加噪训练与筛边前迭代预测；集合权重为 0 只关闭集合约束，MSE 仍然存在。
它们不是推荐对比损失，也不和第一、二阶段的 lambda 混在一起搜索。

步骤 C：相关参数确定后，回查两个候选 K，必要时做少量邻域组合，得到完整配置 P4。
重构器 hidden_dim、time_dim、denoiser_layers、dropout、weight_decay、beta 日程、
训练 batch 和重置策略先保持当前值；只有主要参数效果明确后，再单独提出细调假设。
如果最终融合前对比权重为 0、UB 融合权重为 0 且残差为 0，则重构不再有推荐学习路径，
应记录这种结果并停止无效的 K 搜索，而不是凭重构器自身 loss 选推荐模型参数。

七、最后回查与复验，不打乱四阶段主顺序

1. P1、P2、P3、P4 都是对应阶段的完整配置；进入下一阶段时继承完整优胜设置。
   较好点在边界时补少量值，没有提升时回退到上一阶段基点，不强行宣称新参数更好。
2. P4 确定后，只在第一、二阶段原优胜点附近少量回查损失权重及温度；必要时对 P3
   的前两名融合权重交叉确认，避免把顺序调参得到的局部结果误认为全局最优。
3. 学习率、正则、三类噪声、层权重、容量、残差与内部对比权重都不抢在上述四阶段
   之前搜索。有明确训练不稳定或预算不足的问题时先处理，再对同组候选公平重跑。
   主线完成后若仍有预算，再将这些参数作为额外细调课题，而不是默认必须全部遍历。
4. 最终冻结 1～2 组完整候选，用预先固定的 2026、2027、2028 三个种子独立重复。
   分别按各自验证集选 checkpoint，比较验证 S 的均值和标准差；不挑选有利种子。
   如果差距与波动接近，可预先增加 2029、2030 两个种子，暂不凭单次微小领先宣布胜负。
5. 最终做固定其他参数的消融：两类对比均关闭、仅融合后、仅融合前、两类都开启，
   再比较重构开/关。它说明当前完整配置下的贡献，不等于各变体重新调参后的排名。
6. 每次记录代码版本、完整配置、seed、训练预算、最佳轮次、验证 S、测试四档
   Recall/NDCG、耗时与输出路径。结果写入实验结果存档/ifashion.txt，不填未运行的成绩。
   相同完整配置会复用输出路径；需要独立留档的重复实验使用不同 --info。

当前仅更新本策略文档，未把 config.yaml 的 anchor_cl 开关改为 false，也未运行任何实验。
实际启动第一阶段前，再按本方案准备对应的单值候选配置。所有训练都在服务器进行。


第三项：核心配置四阶段调参策略
确认日期：2026-10-24

一、已经确定的执行顺序

阶段 1：关闭融合前对比，调 c_lambdas、c_temps。
阶段 2：开启融合前对比，固定阶段 1 的优胜组合，调 anchor_cl.anchor_cl_lambda、anchor_cl.temp。
阶段 3：固定两类对比设置，调 fusion_weights.modal_weight。
阶段 4：固定前三阶段设置，调 latent_rebuild.rebuild_k，再调重构学习率、步数和集合损失权重。

本项作为核心执行提纲；具体机制、保存边界和实验说明参见第二项。
当前只是记录策略，没有修改实际配置开关，也没有执行服务器实验。

二、阶段 1：先确定融合后对比

设置 anchor_cl.enabled=false，完整跳过融合前对比计算。
不要将 anchor_cl 整个字典替换为数字 0；如果仅关闭其损失贡献，应将
anchor_cl.anchor_cl_lambda 设为 0.0，但仍开启总开关时会继续计算这一项。

固定：三视图融合权重 [0,0.5,0.5]、重构全部参数、推荐学习率和正则、噪声、层权重、残差。
先固定 c_temps=[0.2]，搜索 c_lambdas；再固定较好的非零权重，搜索 c_temps。
权重粗搜可取 0、0.01、0.03、0.1、0.3；温度可取 0.05、0.1、0.2、0.3、0.5。
零权重作为纯 BPR 对照，不搜索其温度；有希望的非零组合继续局部细搜。
最后用前两名权重和前两名温度做最多四组组合确认，保存完整优胜配置 P1。

三、阶段 2：在融合后基线上加入融合前对比

设置 anchor_cl.enabled=true；固定 P1 的 c_lambdas、c_temps 和其他设置。
user_cl、bundle_cl 均保持 true，四项内部权重保持为 1，先不调内部结构。
先固定 anchor_cl.temp=0.2，搜索 anchor_cl.anchor_cl_lambda；再固定较好的非零权重调温度。
权重可取 0、0.001、0.003、0.01、0.03、0.07、0.1；温度可取 0.05、0.1、0.2、0.3、0.5。
两类温度独立，不要求相同。融合前四项求和、融合后两项平均，不能仅比较权重数值判断强弱。
对优胜区域做小范围权重与温度组合确认，保存完整优胜配置 P2。

四、阶段 3：确定三视图融合权重

固定 P2 的两类对比设置，重构仍使用当前初值。
fusion_weights.modal_weight 的顺序为 [UB,UI,BI]，权重非负、和为 1。
先沿 [0,w,1-w] 搜索 UI/BI 配比，w 可取 0.25、0.4、0.5、0.6、0.75。
再在本阶段内研究 [u,(1-u)w,(1-u)(1-w)]，u 可取 0、0.05、0.1、0.2。
保留较好的完整权重组合，在附近少量交叉确认，保存优胜配置 P3；不强制 UB 权重必须非零。
扩散开启且 UB 最终融合非零时，独立加载最佳模型复评还需要保存并恢复同轮重构图，
当前代码未包含该功能；训练内评估可以计算，具体边界参见第二项。

五、阶段 4：确定重构 Top-K 和相关参数

固定 P3 的损失、融合设置及其他配置，先调 latent_rebuild.rebuild_k。
K 粗搜可取 1、3、5、7、10，在有效区间补相邻整数。K 必须大于 0；
它仅筛选原始已观测 UB 边，不新增边，不缩减 BPR 原始正样本。
选好 K 后，依次调以下 latent_rebuild 内部参数：
1. latent_diffusion_lr：可取 0.0003、0.001、0.003。
2. latent_diffusion_num_steps：可取 6、9、12、16。
3. latent_diffusion_set_loss_weight：可取 0、0.01、0.05、0.1。
一次只调一项，更新基点后再调下一项；结束后回查较好的两个 K，保存完整优胜配置 P4。
如果融合前权重、UB 最终权重和两项残差均为 0，重构没有参与推荐目标的有效学习路径，
应停止无效的重构搜索，不能仅凭重构器自身损失下降认定推荐效果改善。

六、四阶段共同规则与收尾

1. 候选范围是起步建议，并非已验证最佳值；先粗搜，再局部补点，不做所有参数的全网格。
2. 每阶段继承上一阶段的完整优胜配置；阶段最优是其他设置固定时的条件最优。
3. 每个候选单独启动进程，先统一 seed=2026；当前同进程网格不会逐组合重新设置种子。
4. 同组候选保持相同训练预算与评估频率；未充分收敛时统一扩大优秀候选预算后重跑。
5. 按验证集 Recall@20 + Recall@40 + NDCG@20 + NDCG@40 选择参数，不用测试集挑参。
6. P4 确定后，允许在前几阶段优胜附近少量回查，确认交互，不重新展开全范围搜索。
7. 最终对 1～2 组完整候选做 2026、2027、2028 多种子复验，记录均值、标准差及完整配置。
8. lrs、l2_regs、三类噪声、层权重等作为主线完成后的可选补调项，不插入上述主顺序。
9. 新实验真实结果记录到实验结果存档/ifashion.txt；只在服务器训练，不改 NetEase、Youshu。
