
一、关于 DCBR 的处理意见

DCBR 这篇论文与本文模块一存在一定相关性，因为二者都涉及扩散模型和用户-捆绑交互关系的去噪问题。因此，在正式论文写作中不建议完全回避 DCBR。比较稳妥的处理方式是：不在主体对比实验中专门与 DCBR 展开对比，也不在方法部分大篇幅讨论 DCBR，但在 Related Work 中简要提及，并明确说明本文方法与其差异。

这样处理的原因是，如果完全不提 DCBR，而审稿人或老师知道这篇工作，可能会认为相关工作调研不充分，甚至质疑本文有意回避相近工作。相反，如果在相关工作中主动提及并区分，能够说明本文充分了解已有研究，同时也能提前化解相似性带来的风险。

具体写作策略是：DCBR 只在相关工作中出现，不作为本文实验对比的重点。可以将其归入“扩散模型在推荐系统中的应用”或“交互图去噪推荐方法”这一类工作中。写作时重点强调：已有工作尝试使用扩散模型对用户-捆绑交互进行去噪，而本文与这类直接面向交互矩阵或图结构的扩散重建方法不同，本文是在预训练用户-捆绑表示空间中进行潜在偏好去噪，并且只从用户已观测交互中筛选高置信边，以保守方式净化训练期 UB 结构，避免引入未观测的新交互边。

可以采用如下表述：

近年来，扩散模型也被用于推荐系统中的噪声建模与交互去噪。例如，已有工作尝试利用条件扩散模型对用户-捆绑交互关系进行去噪，以缓解观测交互中的噪声问题。与这类直接面向交互矩阵或图结构的扩散重建方法不同，本文侧重于在预训练用户-捆绑表示空间中进行潜在偏好去噪，并仅从用户已观测交互中筛选高置信边，从而以保守方式净化训练期 UB 结构，避免引入未观测交互。

在全文其他部分，需要避免使用过于接近 DCBR 的表述。例如，不建议写“本文首次提出扩散模型用于用户-捆绑交互图去噪”，也不建议写“本文生成去噪后的 UB 图”或“本文重建完整用户-捆绑交互矩阵”。更推荐使用“预训练表示空间中的潜在偏好去噪”“已观测 UB 交互的保守式净化”“高置信训练边筛选”“训练期 UB 结构净化”等表述。

因此，本文对 DCBR 的总体处理原则是：相关工作中主动提及，主体方法中不展开，对比实验中不重点比较，写作中突出本文的差异化定位，即“预训练表示引导的潜在扩散净化”和“只从已观测交互中筛选高置信边”。

二、模块一：预训练表示引导的扩散净化模块

模块一是本文的主要工作之一，也是论文题目“基于预训练表示与扩散净化的捆绑推荐模型”中的核心部分。模块一的定位不是直接生成新的用户-捆绑交互，也不是对完整 UB 交互矩阵进行重建，而是利用预训练用户-捆绑表示，在潜在表示空间中学习用户已观测 bundle 集合的干净偏好表示，并据此从原始已观测交互中筛选高置信边，从而净化训练期 UB 结构。

模块一的动机来自用户-捆绑交互中的噪声问题。在捆绑推荐中，训练集中观测到的用户-捆绑交互并不一定都是同等可靠的。有些交互能够较好地反映用户真实偏好，而有些交互可能只是弱相关、偶然行为或者噪声边。如果直接把所有 UB 边都作为同等可靠的训练监督，模型可能会学习到噪声偏好，进而影响后续表示学习和推荐性能。因此，模块一希望解决的问题是：如何从原始 UB 交互中筛选出更高置信、更可靠的训练边。

模块一的具体流程可以概括为四个阶段。

第一，利用预训练的 UB user embeddings 和 UB bundle embeddings 构建稳定的用户-捆绑表示空间。对于每个用户，取出他在训练集中已经观测到的 bundle 集合，并将这些 observed bundle embeddings 进行集合池化，得到该用户 observed bundle set 的潜在偏好表示，记作 z0。这个 z0 表示用户历史 bundle 集合的整体偏好，而不是某一条单独的边。

第二，对 z0 进行扩散加噪，得到不同时间步下的 noisy latent 表示 zt。这个过程模拟用户偏好表示被噪声污染的情况。随后使用条件去噪网络学习从 zt 恢复到更干净的潜在偏好表示。去噪网络不仅输入 zt，还输入用户向量、zt 与用户向量之间的交互特征、差异特征以及时间步嵌入，从而实现用户条件下的个性化去噪。

第三，通过训练目标约束去噪结果。模块一使用 Diffusion Loss 和 Set Loss。Diffusion Loss 通常采用 MSE，使去噪输出接近原始干净表示 z0，保证重建准确性。Set Loss 约束去噪后的 latent 与用户真实观测过的 bundle 集合保持语义一致，使去噪表示不仅在数值上接近 z0，也能保留 observed bundle set 的推荐语义。简单来说，Diffusion Loss 保证“还原得像不像”，Set Loss 保证“还原后的表示是否仍然符合用户真实交互过的 bundle 集合语义”。

第四，在推理阶段，对于每个用户得到去噪后的干净 latent 表示 z*，然后用 z* 和该用户已观测 bundle embeddings 计算相似度，从 observed bundles 中选出 Top-K 高置信 bundle。最终保留这些高置信 user-bundle 边，构造净化后的 UB 训练图。这里需要强调：模块一不是凭空生成新的用户-捆绑交互，而是在用户原始已观测交互中进行保守式筛选，只保留更可靠的训练边。

模块一在论文中的核心叙事可以概括为：原始 UB 图可能包含噪声边，本文通过预训练表示引导的扩散去噪学习用户 observed bundle set 的干净潜在偏好表示，并基于该表示筛选高置信已观测交互，从而净化训练期 UB 结构，减少噪声监督对后续推荐模型的干扰。

模块一后续实验设计应围绕这个叙事展开。最重要的实验包括：基础消融实验，用来证明开启模块一优于关闭模块一；rebuild_k 敏感性实验，用来说明 Top-K 重建强度对模型性能的影响，并解释过小的 K 会丢失有效监督、过大的 K 会重新引入噪声边，适中的 K 能在去噪和保留有效信号之间取得平衡；重建策略对照实验，用来比较 Random-K、Similarity-K 和 Diffusion-K，证明扩散模型筛选并不是简单随机删边，也不是普通 embedding 相似度筛选，而是扩散去噪 latent 带来的更可靠边选择。

模块一可以在论文中被命名为“预训练表示引导的扩散式 UB 交互净化模块”，英文可表述为 “Pre-trained Representation-guided Diffusion Purification Module” 或 “Latent Diffusion-based UB Edge Purification Module”。其核心贡献不是“首次使用扩散模型处理 UB 图”，而是“在预训练表示空间中对用户已观测 bundle 集合进行潜在偏好去噪，并以保守方式筛选高置信训练边”。

三、模块二：UB 锚定的跨视图对比增强模块

模块二是本文的第二个增强模块，主要用于解决多视图捆绑推荐中的表示不一致问题。MultiCBR 这类多视图捆绑推荐模型通常利用 UB、UI 和 BI 三个视图进行建模。UB 视图表示用户-捆绑直接交互监督，UI 视图表示用户对单个 item 的偏好，BI 视图表示 bundle 内部组成语义。虽然原始 MultiCBR 会对三个视图表示进行融合，但在融合之前，不同视图的表示可能仍然存在明显语义差异。尤其是 UB 视图和 BI 视图，一个偏向交互监督，一个偏向组成语义，二者之间容易存在语义鸿沟。

模块二的动机就是在多视图融合之前增强 UB、UI、BI 三个视图之间的表示一致性，使来自 UI 的用户物品偏好信息和来自 BI 的 bundle 组成语义能够更好地与最终推荐任务相关的 UB 交互空间协同。

模块二采用 UB 锚定的融合前跨视图对比学习。选择 UB 作为 anchor 的原因是，最终任务是预测用户对 bundle 的偏好，而 UB 视图直接对应用户-捆绑交互监督，因此最接近目标任务。模块二以 UB 视图为锚点，引导 UI 视图和 BI 视图向 UB 交互监督空间靠拢，从而提升多视图融合前的表示协调性。

模块二具体包含 user-side 和 bundle-side 两类对齐。

在 user-side，模块二对齐同一个用户在 UB、UI、BI 三个视图下的表示，使用户在不同视图中的偏好表达更加一致。在 bundle-side，模块二对齐同一个正样本 bundle 在 UB、UI、BI 三个视图下的表示，使 bundle 的交互语义、用户偏好语义和组成语义更加协调。

从路径上看，模块二主要包含 UB-UI 和 UB-BI 两类对齐。UB-UI 对齐有助于将用户对 item 的细粒度偏好引入目标交互空间；UB-BI 对齐有助于弥合用户-捆绑交互监督与 bundle-item 组成语义之间的差异。模块二的关键不是简单增加一个对比学习损失，而是将对比学习前移到融合之前，在三视图融合前改善多视图表示质量。

模块二的真实实验结果支持以下叙事。

第一，用户稀疏性实验表明，模块二对训练 UB 交互较少的用户提升更明显，说明它能够缓解 user-side sparse supervision。对于稀疏用户而言，直接 UB 监督不足，而模块二通过跨视图对齐引入 UI 和 BI 中的辅助语义，因此稀疏用户更容易受益。

第二，跨视图表示一致性实验表明，模块二显著提升了融合前多视图表示之间的相似度，尤其是 user-side UB-BI 相似度提升最明显。这说明模块二确实有效缩小了用户在 UB 交互监督视图和 BI 组成语义视图之间的表示差异。

第三，路径贡献实验表明，UB-UI only 和 UB-BI only 均能带来性能提升，Full Module2 同时开启两条路径后取得最优结果。这说明模块二的收益不是来自某一条单独路径，而是来自 UB-UI 与 UB-BI 两类对齐路径的互补作用。实验结果也提示：UB-BI 对齐是最显著的表示变化来源之一，而 UB-UI 对齐对 @20 推荐性能同样重要。

第四，不同 bundle 流行度分组实验表明，模块二对中低频 bundle 尤其是具有一定交互基础但监督仍然不足的 bundle 有明显帮助。这说明模块二并不是只提升热门 bundle，而是能够在一定程度上改善非头部 bundle 的表示学习。

第五，user-side 与 bundle-side 消融实验表明，单独开启 user-side CL 和单独开启 bundle-side CL 都能带来收益，其中 bundle-side 略强，而 Full Module2 最好。这说明用户侧和 bundle 侧对齐并不是互相替代，而是具有互补关系。

第六，BI 视图扰动实验表明，在随机删除不同比例 B-I 边之后，模块二仍然保持优于 Baseline 的效果，说明模块二具有一定结构扰动鲁棒性。但该实验不应被表述为“扰动越强优势越大”，更稳妥的说法是：模块二在不同程度的 BI 结构不完整情况下仍能保持稳定优势。

模块二在论文中的核心叙事可以概括为：原始多视图捆绑推荐模型虽然利用了 UB、UI 和 BI 三个视图，但不同视图之间存在语义差异。本文设计 UB 锚定的融合前跨视图对比学习机制，使 UI 用户偏好语义和 BI 捆绑组成语义在融合前向 UB 交互监督空间对齐，从而提升多视图协同效果，并最终改善推荐性能。

模块二可以命名为“UB 锚定的跨视图对比增强模块”，英文可表述为 “UB-anchored Cross-view Contrastive Enhancement Module”。其核心贡献不是简单添加对比学习损失，而是通过 UB 视图锚定，在融合前增强多视图表示一致性，实现跨视图语义协同。

整篇论文中，模块一和模块二可以统一为一个完整故事：模块一负责净化训练结构，模块二负责增强表示协同。也就是说，本文先通过扩散净化模块过滤不可靠 UB 交互，提供更干净的训练期结构；再通过 UB 锚定跨视图对比学习增强 UB、UI、BI 三视图之间的表示一致性。整体逻辑可以概括为一句话：先净化交互结构，再增强视图协同。
