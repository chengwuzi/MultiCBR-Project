模块一主题三方案记录：观测集合感知的用户偏好扩散式核心边筛选

本文档用于记录围绕模块一的主题三改造方案，供后续开发实现使用。

当前背景：

已有 z0-TopK 对照实验表明，当前模块一的 diffusion-Top3 与 z0-Top3 在 iFashion 上几乎完全贴近。z0-Top3 没有超过 diffusion-Top3，但差距极小。这说明 TopK 保守筛边本身有效，而当前 DiffLoss 导向的扩散 denoiser 相比静态 z0 原型的独立增益很弱。

当前模块一的问题在于：

z0 = mean(observed bundle embeddings)
z_t = add_noise(z0, t)
z_pred = denoiser(z_t, user_vec, t)
L = DiffLoss + set_weight * SetLoss

由于主目标是让 z_pred 恢复 z0，模型很容易学到：

z_star ≈ z0

因此最终 diffusion-TopK 很容易退化为 z0-TopK，难以支撑“扩散去噪显著优于静态原型筛边”的叙事。

主题三的目标是换一个净化对象：不再对 observed-set prototype z0 做扩散净化，而是对 pretrained user embedding 做扩散净化，并让扩散输出直接服务于 TopK 核心训练边选择。


一、主题三的核心定位

主题三建议命名为：

中文：观测集合感知的用户偏好扩散式核心边筛选模块

英文：Observed-set-aware User Preference Diffusion for Core UB Edge Selection

它的核心思想不是训练一个普通的推荐用户向量，而是训练一个用于已观测 UB 边筛选的 selector query。

一句话定义：

对预训练用户偏好表示进行 observed-set-aware 扩散扰动与去噪，得到用于已观测 UB 边筛选的用户偏好 query；训练时从用户历史中随机藏起一小组 target bundles，通过 soft core edge selection 从剩余 observed bundles 中得到核心边集合表示，并用该核心集合表示预测 target bundles 的稳健中心，使扩散输出直接服务于高质量 TopK 训练边选择；推理时仅从用户原始 observed bundles 中保守筛选 TopK 边，用于下游捆绑推荐训练。

主题三仍坚持保守式筛边原则：

1. 只从用户原始 observed bundles 中选边。
2. 不生成未观测 user-bundle 边。
3. 不重建完整 UB 矩阵。
4. 最终目标是构造更高质量的训练期 UB 图，服务下游 DWT / CBR 捆绑推荐。


二、与当前模块一的区别

当前模块一：

净化对象：observed-set prototype z0
辅助条件：pretrained user embedding e_u
训练目标：z_pred 恢复 z0，并保持 observed set 语义一致
推理筛边：用 z_star 在 observed bundles 内选 TopK

主题三：

净化对象：pretrained user embedding e_u
辅助条件：observed-set prototype z0
训练目标：由扩散 query 选出的核心边集合能预测 held-out target set 的稳健兴趣中心
推理筛边：用 denoised user preference query 在 observed bundles 内选 TopK

可以理解为：

当前模块一：用 user embedding 辅助净化 z0。

主题三：用 observed-set context 辅助净化 user embedding。


三、符号定义

对用户 u：

e_u：预训练 user embedding。

O_u：用户 u 在训练集中已观测到的 bundle 集合。

E_b：预训练 bundle embedding 表。

z0_u：用户 observed bundle set 的集合语义表示。

z0_u = mean(emb(b)), b in O_u

e_t：对 e_u 加噪后的 noisy user preference embedding。

q_u：denoiser 输出的 denoised user preference query。

P_u：从 O_u 中随机藏起来的一小组 held-out target bundles。

target_num：P_u 中包含的 target bundle 数量。iFashion 第一阶段固定为 4。

g_u：held-out target set 的稳健中心表示。

g_u = mean(emb(p)), p in P_u

C_u：训练时用于软选择核心边的候选集合。

C_u = O_u - P_u

r_u：由 q_u 从 C_u 中软选择得到的核心边集合表示。

n_u：用户未交互过的 negative bundle。


四、扩散过程

主题三对 pretrained user embedding e_u 进行加噪：

e_t = sqrt(alpha_bar_t) * e_u + sqrt(1 - alpha_bar_t) * epsilon

其中：

t 为扩散时间步；
epsilon 为高斯噪声；
alpha_bar_t 由 beta schedule 累积得到，沿用当前 LatentDiffusionRebuilder 中的实现方式即可。

扩散过程的意义：

1. 模拟用户偏好表示受到噪声污染。
2. 迫使 denoiser 从不同噪声强度下恢复稳定的用户偏好筛边 query。
3. 避免直接依赖静态 pretrained user embedding。


五、Denoiser 输入设计

主题三 denoiser 的输入为：

[e_t, z0_u, e_t * z0_u, |e_t - z0_u|, time_embedding(t)]

各项含义如下。

1. e_t

加噪后的用户偏好表示。

含义：

当前被扰动的用户偏好状态。

作用：

作为扩散模型的主要输入，让 denoiser 学会从 noisy user embedding 中恢复稳定筛边 query。

维度：

[batch_size, embedding_dim]


2. z0_u

用户 observed bundle set 的均值表示。

z0_u = mean(emb(b)), b in O_u

含义：

用户真实训练交互集合的语义上下文。

作用：

帮助 denoiser 感知用户实际交互过的 bundle 集合，避免主题三退化成纯 user embedding denoising。

维度：

[batch_size, embedding_dim]


3. e_t * z0_u

e_t 与 z0_u 的逐元素乘法。

含义：

用户预训练偏好与 observed-set 语义之间的交互特征。

作用：

如果某些维度在 e_t 和 z0_u 中同时较强，说明该偏好方向同时被用户表示和 observed set 支持。

维度：

[batch_size, embedding_dim]


4. |e_t - z0_u|

e_t 与 z0_u 的逐元素绝对差。

含义：

用户预训练偏好与 observed-set 语义之间的偏差。

作用：

帮助 denoiser 判断用户表示与 observed set 之间的不一致部分，这些不一致可能来自噪声交互、弱偏好边或预训练表示偏移。

维度：

[batch_size, embedding_dim]


5. time_embedding(t)

时间步嵌入。

含义：

当前噪声强度。

作用：

告诉 denoiser 当前输入处于哪个扩散噪声阶段。

维度：

[batch_size, time_dim]


拼接后的输入维度：

4 * embedding_dim + time_dim

若 embedding_dim=64，time_dim=16，则输入维度为：

4 * 64 + 16 = 272

Denoiser 输出：

q_u = denoiser([e_t, z0_u, e_t * z0_u, |e_t - z0_u|, time_embedding(t)])

q_u 的维度为：

[batch_size, embedding_dim]

q_u 的语义：

q_u 不是普通推荐 user embedding，而是用于从 observed bundles 中筛选核心训练边的 denoised user preference query。


六、主训练目标：核心边集合预测 held-out target set 中心

主题三最重要的设计是：不直接训练 q_u 本身做普通推荐，而是训练 q_u 选出的核心边集合是否有用。

具体流程如下。

1. 对用户 u，从 O_u 中随机采样一小组 observed bundles 作为 held-out target set：

P_u subset O_u

iFashion 第一阶段固定：

target_num = 4

即每个用户训练时随机藏起 4 个 observed bundles。

2. 构造 target set 的稳健中心：

g_u = mean(emb(p)), p in P_u

这里的 g_u 表示被藏起那一小组历史交互的共同兴趣方向。

从单个 p_u 改为 P_u 的原因是：单条 observed edge 可能本身就是噪声，若强行预测它，会把 denoiser 的训练方向带歪。使用 4 个 target bundles 的 mean 中心，可以稀释单条噪声边影响，让主监督更接近用户稳定兴趣。

3. 构造候选集合：

C_u = O_u - P_u

4. 使用 q_u 对 C_u 中每个 bundle 打分：

score_i = cosine(q_u, emb(b_i)), b_i in C_u

5. 使用 soft selection 得到核心边集合表示。

第一版建议直接使用 softmax selection：

w_i = softmax(score_i / tau_select)

r_u = sum(w_i * emb(b_i)), b_i in C_u

其中：

tau_select 为 soft selection 温度。

r_u 表示由 q_u 从用户 observed candidates 中软选择出的核心边集合表示。

6. 采样 negative bundle：

n_u not in O_u

7. 使用 r_u 去预测 held-out target set 的中心：

score_pos = cosine(r_u, g_u)

score_neg = cosine(r_u, emb(n_u))

8. 主损失：

L_core = -log sigmoid(score_pos - score_neg)

也就是：

L_core = -log sigmoid(cosine(r_u, g_u) - cosine(r_u, emb(n_u)))

该目标的意义：

由 q_u 选出的核心 observed bundles 应该能够代表用户，并预测用户另一小组真实 observed bundles 的共同兴趣中心，而不是死记或解释某一条可能有噪声的单边。

这与最终目标高度一致：

保留少量高质量 observed UB 边，使它们作为训练监督服务下游捆绑推荐。

iFashion 训练 UB 分布支持 target_num=4：

用户数：53897

训练 UB 交互数：1213676

所有用户都有训练 UB 交互。

每用户训练 UB 数最小值为 14，平均值为 22.52，中位数为 19。

因此即使每次藏起 4 条 target edges，最少仍有 10 条 observed candidates 可供 q_u 软选择；而最终 rebuild_k=3，所以候选集合规模足够。


七、为什么不直接用普通 BPR 训练 q_u

不建议第一版只使用：

score_pos = cosine(q_u, g_u)

score_neg = cosine(q_u, emb(n_u))

L_query = -log sigmoid(score_pos - score_neg)

因为这种目标只训练 q_u 本身是否是一个好的推荐查询向量，并没有直接约束 q_u 选出的 TopK observed edges 是否是高质量训练边。

当前研究目标不是让 q_u 直接做最终推荐，而是让 q_u 服务于：

observed edge selection

因此主目标必须落在核心边集合 r_u 上，而不是只落在 q_u 本身上。


八、辅助损失设计

开发时建议把以下三个辅助损失都实现出来，但第一阶段默认关闭或权重设为 0。

第一阶段只启用主损失 L_core，先判断主题三是否有基本价值。

如果 L_core 版本能够超过 z0-Top3 / diffusion-Top3，再逐步打开辅助损失进行调参。


1. L_query：query-level ranking loss

定义：

q_u 本身也应该能把 held-out target set 的中心 g_u 排在 negative bundle 前面。

第一阶段 target set 版本中，可定义为：

score_pos_query = cosine(q_u, g_u)

score_neg_query = cosine(q_u, emb(n_u))

L_query = -log sigmoid(score_pos_query - score_neg_query)

作用：

防止 q_u 完全漂掉，使 q_u 保持基本的正负 bundle 辨别能力。

定位：

辅助项，不是主目标。

建议初始权重：

lambda_query = 0

若主损失有效但训练不稳定，可尝试：

lambda_query = 0.05 或 0.1


2. L_consistency：noise consistency loss

定义：

对同一用户采样两个不同噪声版本：

e_t1 = q_sample(e_u, t1)

e_t2 = q_sample(e_u, t2)

q_u1 = denoiser(e_t1, z0_u, t1)

q_u2 = denoiser(e_t2, z0_u, t2)

要求两个输出 query 保持一致：

L_consistency = 1 - cosine(q_u1, q_u2)

作用：

让同一用户在不同噪声扰动下得到稳定的核心边筛选 query。

定位：

辅助稳定项。

建议初始权重：

lambda_consistency = 0

若主损失有效但输出波动较大，可尝试：

lambda_consistency = 0.05


3. L_anchor：small anchor loss

定义：

用极小权重约束 q_u 不要完全偏离 pretrained user embedding e_u。

可选形式一：

L_anchor = 1 - cosine(q_u, e_u)

可选形式二：

L_anchor = MSE(q_u, e_u)

建议优先使用 cosine anchor，因为它只约束方向，不强行恢复数值。

作用：

提供轻微稳定锚点，避免 q_u 在早期训练中完全漂移。

定位：

极小辅助项，只做稳定，不做主目标。

建议初始权重：

lambda_anchor = 0

若训练出现明显不稳定，可尝试：

lambda_anchor = 0.001

不建议使用较大 anchor 权重，否则会退化为：

q_u ≈ e_u

从而再次引发“为什么不直接用 e_u 选 TopK”的质疑。


九、第一阶段推荐总损失

第一阶段只启用主损失：

L = L_core

配置上建议：

lambda_query = 0
lambda_consistency = 0
lambda_anchor = 0

第一阶段目标不是一次性调出最优，而是判断主题三是否具备基本价值：

theme3-Top3 是否超过 z0-Top3 和当前 diffusion-Top3。

若 L_core 版本有效，再进入第二阶段：

L = L_core + lambda_query * L_query

若第二阶段有效但不稳定，再进入第三阶段：

L = L_core + lambda_query * L_query + lambda_consistency * L_consistency

最后才考虑极小 anchor：

L = L_core + lambda_query * L_query + lambda_consistency * L_consistency + lambda_anchor * L_anchor


十、推理阶段

训练完成后，对每个用户 u：

1. 构造 observed-set context：

z0_u = mean(emb(b)), b in O_u

2. 从 pretrained user embedding e_u 得到 denoised user representation：

e_star = refine_user_query(e_u, z0_u)

当前默认 objective=user_reconstruction，因此推理阶段与原模块一保持一致，使用 12-step iterative refinement：

q = e_u

for step in reversed(range(num_steps)):

    q = denoiser(q, z0_u, step)

e_star = q

说明：

如果 objective=core_prediction，则曾经建议使用 one-step 推理以避免训练/推理分布偏移。但当前最终开发版已经切换为朴素用户表示重建：

e_t = q_sample(e_u, t)

e_pred = denoiser(e_t, z0_u, t)

L_reconstruct = MSE(e_pred, e_u)

因此当前实验为了和原模块一口径一致，默认使用 iterative 推理。

3. 使用 e_star / q_u 对完整 O_u 中所有 observed bundle 打分：

score_b = cosine(q_u, emb(b)), b in O_u

4. 保留 TopK：

S_u = TopK(score_b), S_u subset O_u

5. 构造 rebuilt UB graph：

只保留 (u, b), b in S_u

该 rebuilt UB graph 继续送入 DWT / CBR 下游训练流程。

UserPreferenceDiffusionRebuilder 建议包含：

十二、训练 batch 中需要补充的信息

当前 build_observed_bundle_batch 返回：

user_indices
observed_indices
observed_mask

主题三第一版可以继续使用这些信息。

training_loss 内部需要完成：

1. 对每个用户从 observed_indices 中随机采样 target_num 个 held-out target bundles，构成 P_u。

2. 将 P_u 从 candidate mask 中去掉，得到 C_u。

3. 对 P_u 中 bundle embedding 做 mean pooling，得到 target center：

g_u = mean(emb(p)), p in P_u

4. 从全量 bundle 中为每个用户采样 negative n_u，要求 n_u 不在该用户 observed set 中。

注意：

如果某个用户 observed 数量不足以同时构造 P_u 和 C_u，则需要退化处理。iFashion 训练集中每个用户最少有 14 条 UB 训练交互，target_num=4 时不会触发该问题，但代码仍需防御：

observed_count <= target_num 的用户可以跳过，或者将当前 batch 内该用户的 target_num 临时降为 max(1, observed_count - 1)。


十三、soft selection 细节

第一版建议不用 hard TopK，因为 hard TopK 不可导。

使用 softmax over candidates：

w_i = softmax(score_i / tau_select)

r_u = sum(w_i * emb(b_i))

这样梯度可以从 L_core 回传到 q_u 的打分逻辑。

可配置参数：

tau_select

建议初始值：

tau_select = 0.1 或 0.2

如果 softmax 太尖锐，训练可能不稳定；
如果 softmax 太平，r_u 会接近所有候选的平均，容易退化回 z0。

后续可考虑 top-k masked softmax：

前向先选 top-k mask，只在 top-k 内做 softmax 聚合。

但第一版建议先用完整 candidate softmax，降低开发复杂度。


十四、开发实现时的关键细节

为避免后续开发时出现理解偏差，第一版实现需要注意以下细节。

1. target 采样只从有效 observed 位置中采样。

observed_indices 中 padding 位置为 -1，不能参与 P_u 采样。

实现时应基于 observed_mask 得到每个用户的有效 observed positions，再随机采样 target_num 个位置作为 P_u。

2. candidate mask 必须排除 P_u。

候选集合为：

C_u = O_u - P_u

实现上可构造：

candidate_mask = observed_mask，并将 target positions 置为 0。

soft selection 只在 candidate_mask=1 的位置上做 softmax。

3. target center 使用 P_u 中 bundle embedding 的 mean pooling。

第一版不做复杂加权：

g_u = mean(emb(p)), p in P_u

这里 emb(p) 使用外部预训练 bundle embedding，与当前 LatentDiffusionRebuilder 中的 bundle_embeddings 来源保持一致。

4. cosine 前建议显式 normalize。

计算 score_i、score_pos、score_neg 时建议使用 F.normalize 后点积，避免向量尺度影响相似度：

score_i = dot(normalize(q_u), normalize(emb(b_i)))

score_pos = dot(normalize(r_u), normalize(g_u))

score_neg = dot(normalize(r_u), normalize(emb(n_u)))

5. r_u 的构造需要保留梯度回传到 q_u。

bundle_embeddings 可以是固定 buffer，但 softmax 权重 w_i 来自 q_u 的打分，因此：

r_u = sum(w_i * emb(b_i))

必须保持 w_i 的计算链路可导，不要在 soft selection 处 detach。

6. 第一版推理阶段不使用 target set。

P_u、g_u 只用于训练 L_core。

推理时对完整 O_u 打分，直接 hard TopK：

score_b = cosine(q_u, emb(b)), b in O_u

S_u = TopK(score_b)

7. 负采样使用 hard negative 增强主损失。

negative bundle n_j 需要满足：

n_j not in O_u

当前建议：

neg_num_for_core = 8

neg_sampling = hard

即每个用户采样 8 个随机未交互 bundle，并取其中与 r_u 相似度最高的 hardest negative 进入 L_core。


十五、负采样策略

当前主题三使用 hard negative 增强主损失：

对每个用户随机采样多个 bundle n_j，要求 n_j 不在 O_u。

默认：

neg_num_for_core = 8

neg_sampling = hard

实现方式不是从全量 bundle 精确搜索 hard negative，而是先随机采样 8 个未交互 bundle，再取其中与 r_u 相似度最高的作为当前 batch 的 hardest negative。

这样比单个 random negative 更难，但计算成本仍然可控。

十八、预期风险

1. L_core 可能训练不稳定。

原因：

soft selection 的 r_u 依赖 q_u 的打分分布，温度 tau_select 对结果影响较大。

应对：

先调 tau_select，再考虑打开 lambda_query。


2. target set 中仍可能混入噪声边。

原因：

主题三仍然把 observed bundles 作为弱监督来源，不能保证每条历史边都是真实核心偏好。

应对：

第一阶段不用单个 held-out positive，而是固定 target_num=4，并用 g_u = mean(emb(p)), p in P_u 作为目标中心，以降低单条噪声边对主损失的影响。

如果后续发现训练目标仍然不稳，再考虑 target set 内部的轻量加权平均，但第一版不建议引入预训练 UB 点积分数作为硬监督，以免退化为复刻 e_u/z0 相似度规则。


3. soft selection 可能退化为 z0。

原因：

如果 softmax 太平，r_u 接近候选集合均值。

应对：

降低 tau_select，或后续使用 top-k masked softmax。


4. q_u 可能变成普通推荐向量。

原因：

如果 L_query 权重过大，模型目标会偏向 q_u 本身推荐，而不是核心边集合有效性。

应对：

第一阶段关闭 L_query，后续只用小权重。


5. anchor 权重过大会导致退化。

原因：

如果强约束 q_u 接近 e_u，会再次出现“为什么不直接 e_u TopK”的质疑。

应对：

lambda_anchor 设为 0 或 0.001。


6. 主题三不一定优于主题二。

主题三更换了净化对象，故事更自然，但它不如主题二那样直接沿着 observed-set prototype 做 selector 学习。

如果主题三失败，不代表任务导向 TopK 思路失败，仍应继续考虑主题二。


十九、最终开发原则

第一版开发必须保持克制：

1. 新增 UserPreferenceDiffusionRebuilder，不覆盖当前 LatentDiffusionRebuilder。

2. 第一阶段只启用 L_core。

3. L_query、L_consistency、L_anchor 都实现成可配置项，但默认权重为 0。

4. 推理阶段仍只从 observed bundles 中 hard TopK。

5. 第一阶段只在 iFashion 上验证 theme3-Top3。

6. 目标是超过 z0-Top3 / current diffusion-Top3，而不是只超过 origin。

7. 如果第一阶段不超过 0.13148 NDCG@20，不建议继续大规模调参。


二十、最终简短结论

主题三不是简单的“用户表示加噪降噪”，而是“用户偏好扩散 query 驱动的 observed edge selection”。

其关键是：

扩散输出 q_u 必须通过核心边集合 r_u 的预测效用来训练，而不是只通过 q_u 自身的普通 BPR 来训练。

第一阶段只启用主损失 L_core：

从 observed set 中藏起 target_num=4 个 target bundles；
将这 4 个 target bundles 的 mean pooling 表示作为 g_u；
用 q_u 在剩余 observed bundles 中软选择核心集合 r_u；
用 r_u 预测 g_u，并区分 negative bundle。

如果该方案能超过 z0-Top3 / diffusion-Top3，则说明主题三具备继续调参和写入论文故事的价值。



二十一、主题三第一阶段参数指导

主题三会引入一些新参数，但不应从零开始大规模网格搜索。基于当前模块一、z0-TopK 对照实验以及 iFashion 上已有结果，第一阶段应尽量固定大部分参数，只小范围探索最关键的新参数。


1. 建议直接沿用当前模块一的参数

以下参数建议第一阶段直接沿用当前模块一，不要改：

num_steps: 12

beta_start: 1.0e-4

beta_end: 0.02

hidden_dim: 128

time_dim: 16

denoiser_layers: 2

dropout: 0.1

lr: 1.0e-3

weight_decay: 1.0e-5

batch_size: 1024

infer_batch_size: 256

rebuild_k: 3

原因：

当前完整模块一 diffusion-Top3 至少没有输给 z0-Top3，说明当前扩散步数、beta schedule、网络容量、学习率和 batch 设置并不离谱。

主题三第一阶段的核心目的是验证“净化对象从 z0 改为 e_u，并使用任务导向 L_core”是否有效，而不是同时重新搜索所有底层训练参数。


2. 第一阶段最关键的新参数：tau_select

tau_select 控制 soft selection 的尖锐程度：

tau_select 越小，soft selection 越接近 hard TopK；

tau_select 越大，soft selection 越接近平均池化，容易退化为类似 z0 的表示。

建议初始值：

tau_select = 0.1

第一阶段只建议小范围尝试：

tau_select in [0.05, 0.1, 0.2]

不建议一开始做更大范围搜索。

如果 tau_select=0.2 效果差，可能说明 soft selection 太平，r_u 接近 observed candidates 的均值。

如果 tau_select=0.05 训练不稳定，则优先回到 tau_select=0.1。


3. 辅助损失权重的调参顺序

第一阶段默认关闭所有辅助损失：

lambda_query = 0.0

lambda_consistency = 0.0

lambda_anchor = 0.0

即第一阶段只启用：

L = L_core

如果只使用 L_core 的版本已经表现出价值，再按以下顺序逐步打开辅助损失。


第一步：lambda_query

可尝试范围：

lambda_query in [0.05, 0.1]

作用：

让 q_u 本身保留基本正负 bundle 辨别能力，防止 q_u 完全漂掉。

注意：

lambda_query 不建议超过 0.1，否则主题三可能退化为普通 query-level ranking 模型，而不是核心边集合选择模型。


第二步：lambda_consistency

可尝试范围：

lambda_consistency in [0.02, 0.05]

作用：

让同一用户在不同噪声扰动下得到更稳定的 q_u。

注意：

建议在 lambda_query 已经确认有效或主损失训练存在波动时再试，不要第一阶段直接加入。


第三步：lambda_anchor

可尝试范围：

lambda_anchor in [0.0, 0.001]

作用：

给 q_u 一个极小的方向稳定锚点，避免训练早期完全漂移。

推荐形式：

L_anchor = 1 - cosine(q_u, e_u)

注意：

lambda_anchor 不能过大，否则 q_u 会被强行拉回 e_u，重新引发“为什么不直接 e_u TopK”的质疑。


4. held-out target set 数量

第一阶段固定：

target_num = 4

原因：

原先设想的单 held-out positive 容易被噪声边污染。若随机藏起的单个 p_u 本身是弱偏好或偶然交互，L_core 会错误地逼迫 q_u 选择一组核心边去解释该噪声边。

修正后采用一小组 target bundles，并用其 mean pooling 中心作为监督目标：

P_u subset O_u, |P_u| = target_num

g_u = mean(emb(p)), p in P_u

iFashion 训练 UB 统计支持 target_num=4：

每个用户训练 UB 交互最少为 14，平均为 22.52，中位数为 19。

藏起 4 条 target edges 后，最少仍剩 10 条 candidate edges；最终 rebuild_k=3，因此候选集合足够。

target_num=4 的定位是：在不明显稀释目标兴趣的前提下，降低单条噪声 observed edge 对主损失的影响。


5. negative 数量与 hard negative

原始第一阶段曾固定：

neg_num_for_core = 1

但从 theme3_tau0.1_tgt4 的早期日志看，L_core 很快从 0.423 左右降到 0.419 左右后进入平台区。这说明模型能较容易地区分 target set center 和随机负样本，但该监督压力不足以继续逼出更好的核心边选择。

因此修正后的主题三第一阶段建议使用 harder negative：

neg_num_for_core = 8

neg_sampling = hard

做法：

对每个用户随机采样 8 个不在 O_u 中的 negative bundles：

n_1, ..., n_8 not in O_u

计算：

score_neg_j = cosine(r_u, emb(n_j))

取 hardest negative：

score_neg = max_j score_neg_j

主损失变为：

L_core = softplus(-(score_pos - score_neg))

其中：

score_pos = cosine(r_u, g_u)

这样可以增强主损失压力，避免模型只学到“历史均值能打过随机负样本”的简单解。

如果 hard negative 训练不稳定，可临时退回：

neg_num_for_core = 1

neg_sampling = random


6. soft selection 候选范围

第一阶段使用完整候选集合：

C_u = O_u - P_u

即从除 held-out target set 之外的所有 observed bundles 中做 soft selection。

第一阶段不建议上来就做 top-k masked softmax。

如果后续发现 r_u 仍然退化得接近 z0，可再尝试：

selection_mode = topk_softmax

selector_train_k = 3 或 6

但这属于第二阶段。

二十二、当前最终开发版修正：朴素用户表示去噪重建

经过 theme3 target-set L_core、one-step 推理、hard negative 等实验后，当前主题三开发版做一次收敛修正：不再默认使用复杂的核心边预测损失，而是回到与原模块一最一致的朴素扩散去噪范式。

当前默认 objective：

objective = user_reconstruction

核心思想：

对原始预训练用户表示 e_u 加噪；

denoiser 结合 observed-set context z0_u 进行降噪；

训练目标直接回归加噪前的干净用户表示 e_u；

推理阶段沿用原模块一的 12-step iterative refinement；

最后用降噪后的用户表示在 observed bundles 中选择 TopK。

该版本对应的训练过程为：

z0_u = mean(emb(b)), b in O_u

t ~ Uniform(0, ..., num_steps - 1)

epsilon ~ N(0, I)

e_t = sqrt(alpha_bar_t) * e_u + sqrt(1 - alpha_bar_t) * epsilon

e_pred = denoiser([e_t, z0_u, e_t * z0_u, |e_t - z0_u|, time_embedding(t)])

L_reconstruct = MSE(e_pred, e_u)

当前默认不启用：

L_core

target set prediction

hard negative ranking

L_query

L_consistency

L_anchor

这些复杂项只作为历史实验分支保留，不再作为当前主题三主线。

推理阶段为：

q = e_u

for step in reversed(range(num_steps)):

    q = denoiser(q, z0_u, step)

score_b = cosine(q, emb(b)), b in O_u

S_u = TopK(score_b), S_u subset O_u

这样做的原因：

1. 与原模块一实现口径保持一致。

原模块一是：

z_t = add_noise(z0, t)

z_pred = denoiser(z_t, user_vec, t)

L = MSE(z_pred, z0) + SetLoss

推理时用 iterative refinement。

当前修正版只是把净化对象从 z0 换为 e_u：

e_t = add_noise(e_u, t)

e_pred = denoiser(e_t, z0_u, t)

L = MSE(e_pred, e_u)

推理同样使用 iterative refinement。

2. Loss 足够简单，避免复杂监督带来的解释困难。

此前 L_core 版本需要考虑 target set 噪声、mean center 是否过平、random negative 是否太弱、hard negative 是否过强等问题。当前版本直接回归干净用户表示，实验含义更清楚：

observed-set-aware diffusion 是否能把 pretrained user embedding 净化成更适合筛选 observed UB 边的表示。

3. 仍然保留 observed-set-aware 条件。

虽然 loss 是 MSE(e_pred, e_u)，但 denoiser 输入仍包含 z0_u、e_t * z0_u、|e_t - z0_u|，因此该模块不是纯 user embedding autoencoder，而是由用户历史 observed bundle set 条件化的用户表示净化。

当前推荐配置：

user_pref_diffusion:

  enabled: true

  objective: user_reconstruction

  hidden_dim: 128

  time_dim: 16

  denoiser_layers: 2

  dropout: 0.1

  num_steps: 12

  beta_start: 1.0e-4

  beta_end: 0.02

  lr: 1.0e-3

  weight_decay: 1.0e-5

  batch_size: 1024

  infer_batch_size: 256

  infer_mode: iterative

  infer_step: 0

  lambda_query: 0.0

  lambda_consistency: 0.0

  lambda_anchor: 0.0

说明：

target_num、neg_num_for_core、neg_sampling、tau_select 等参数仍保留在代码中，是为了兼容旧的 core_prediction objective；在 objective=user_reconstruction 时不参与训练。

当前判定实验：

只跑 iFashion。

rebuild_k = 3。

目标仍是超过或接近：

z0-Top3 NDCG@20 = 0.13145

current diffusion-Top3 NDCG@20 = 0.13148

如果该朴素用户表示重建版本仍然明显低于上述对照线，则主题三可以正式停止推进，后续转向主题二或 BI 关系提炼。
